## 결론

**지금 할 일은 기존 부트스트랩 실행기의 확인된 안전성 결함 F1–F3 수정과 그에 대응하는 최소 회귀 검증뿐이다.** 이때 **기존 도구의 기본 동작, 프로젝트의 정본·native 설정/lock, 사용자 전역 설정을 가능한 한 그대로 활용한다.** 안전성과 재현성을 해치지 않는 값을 단지 통제 가능성을 높이겠다는 이유로 덮어쓰지 않는다. 이 작업을 계기로 환경변수 설정·차단 목록, CLI 옵션, 설치 경로, OS별 분기, 신규 검증 프레임워크를 확장하지 않는다. PR은 수정·검증 전까지 Draft로 유지한다.

최근 [PR Gate](https://github.com/mols3131d/mols-agent-assets/actions/runs/40175129918)는 **Pass**이며 문서 인덱스(F4)는 PR diff에 반영됐다. 다만 F1–F3용 회귀 사례는 현재 테스트에 없고, CI 성공을 이 결함들의 해결로 간주하지 않는다. 과거 재현 근거와 미검증 범위는 [격리 검토](bootstrap-isolation-review-2026-10-25.md)에 기록돼 있다.

## 기존 기본값·프로젝트 설정·전역 설정 활용 원칙

**기존 동작 우선, 필요한 예외만 국소적으로 적용한다.** 우선순위를 전역 설정 무시나 새 설정 강제로 오해하지 않는다.

- **프로젝트에서 결정한 사항:** [개발환경 정본](../../docs/development/development-environment.md), `mise.toml`, `.python-version`, `pyproject.toml`, `uv.lock` 및 도구 자체의 native 설정/lock이 해당 범위를 소유한다. 문서는 정책 판단에 사용하고 **실행기는 문서를 파싱하거나 정책을 중복 하드코딩하지 않는다**.
- **별도 선언이 없는 사항:** Git/mise/uv/Python의 native 기본 동작을 그대로 사용한다. 이미 구성된 사용자 `PATH`, 프록시, 인증, 사내 registry/index, 캐시 위치 및 관련 전역 설정은 **프로젝트 계약과 호환되면 유지·활용**한다. 문제가 없는 전역 값을 초기화하거나 복제 설정하지 않는다.
- **재사용 범위 구분:** 호환되는 기존 Git·Shell·허용된 Python 인터프리터와 mise-managed 설치/캐시는 재사용한다. 그러나 전역 Python 패키지·Ruff·임의 전역 Node/CLI는 프로젝트 `.venv` 및 pin/lock의 대체물이 아니다. 전역 설정을 보존하는 것과 전역 환경을 프로젝트 의존성으로 사용하는 것은 다르다.
- **충돌 시에만 예외:** 전역 환경이 실제 대상 Git 저장소, 필요한 uv 그룹, project-local `.venv`, pin/lock 또는 승인된 쓰기 범위를 위반한다면 해당 명령의 옵션·사전 검사 등 **가장 좁은 경계**에서 충돌을 해소한다. 안전하게 해소할 수 없으면 중단하고 이유를 안내한다. 사용자의 전역 설정을 편집하지 않는다.
- **기존 강제값도 재검토:** 현재 runner가 지정하는 Git/uv/mise 환경변수 7개, 제거하는 6개, Node를 위한 child `PATH` 조정은 **전부 유지해야 하는 고정 계약이 아니다**. 이미 project config나 command flag가 소유하는 중복값을 우선 검토한다. 다만 제거 전에 필요한 safety/Windows npm 실행 경로에 영향이 없는지 확인하고, 무작정 삭제하지 않는다.

판정 순서는 **프로젝트의 명시적 계약 확인 → 기본·전역 설정으로 충족하는지 확인 → 실제 충돌이 있을 때만 국소 수정**이다. 특별한 문제가 없는 환경에서 추가 설정·설치·검사는 하지 않는다.

## 환경변수에 관한 제한

- **추가하는 환경변수 기본값은 0개.** 설치·안전성 문제를 해결한다는 명목으로 `self.env`에 새 강제값을 쌓지 않는다. 현재 설정도 그대로 당연시하지 않는다. 새 항목 추가·기존 항목 유지/변경이 불가피하면 **어떤 확인된 계약/실패를 해결하는지** 먼저 명시한다.
- `GIT_*` 전체 삭제, `UV_*` 전체 삭제, 광범위한 환경변수 allowlist/denylist, OS별 환경변수 매트릭스를 만들지 않는다. 프록시·인증·사내 패키지 인덱스처럼 정상적인 사용자 환경도 보존한다.
- 필요하다면 **해당 Git 또는 uv subprocess에만** 좁게 적용한다. 부트스트랩 전 과정의 공통 환경을 일괄 재설계하거나 사용자 시스템의 환경변수를 변경하지 않는다.
- 프로젝트 native 설정과 기본 동작만으로 충분하다면 별도 환경변수나 명시적 인자 자체를 추가하지 않는다. 실제 충돌이 있을 때는 명시적 인자·사전 검증·즉시 중단 등 더 좁고 이해하기 쉬운 해법을 우선 검토한다. 선택지별 코드를 함께 구현하지 않는다.
- 발견 가능한 모든 환경변수를 선제 열거하지 않는다. **재현 사례 → 최소 경계 수정 → 회귀 테스트**가 없으면 범위를 늘리지 않는다.

## 이번 PR 개선 단계에서 하지 않을 일

- CLI 도구의 bounded latest 업데이트, `mise.lock`/sidecar 정책 도입, 다중 OS 지원 확대. 현재 `update`의 **Python 의존성 한정** 동작은 알려진 제약으로 남긴다. 원래 목표를 변경할지는 별도 결정하고, F1–F3 수정에 끼워 넣지 않는다.
- `--yes`, `--force`, `--global`, 전용 승인 시스템, 일반 목적 설치 관리자, 환경 탐색·복구 프레임워크 도입.
- `HOME` Skill, Rulesync projection, Git hooks, shell profile, OS 전역 도구의 자동 변경.
- PR #256의 범용 설계 Skill·Eval 수정, 문서 대량 재작성, 추가 테스트 플랫폼의 결과를 얻기 위한 무허가 설치.

## 구현자에게 인계할 실행 순서

1. **F1 → F2 → F3** 순서로 현재 project/native 설정과 정상적인 사용자 전역 설정으로 해결 가능한 부분을 먼저 확인한다. 필요한 경우에만 기존 함수 안에서 작은 수정과 직접 대응하는 테스트를 작성한다. 다른 실패 사례가 보이면 먼저 재현·영향을 기록하고 **기본 작업에 자동 편입하지 않는다**.
2. 코드와 테스트의 diff에서 **신규·기존 강제 환경변수의 필요성, 범위 밖 파일, 불필요한 옵션·추상화**를 확인한다. 새 환경변수는 직접적인 실패 근거 없이는 추가하지 않고, 기존 설정 제거도 회귀 위험과 실제 동작을 보고 판단한다.
3. 기존 테스트 및 PR Gate로 정상 동작을 확인한다. 실제 설치·업데이트는 [정본](../../docs/development/development-environment.md)에 따른 **사용자 사전 허가 없이 실행하지 않는다**. 위험 없는 임시 fixture 검증과 실제 사용자 환경 변경을 구분한다.
4. 결과는 각 F1–F3에 대해 **해결 근거 / 실행한 검증 / 미검증 항목**만 간결히 보고한다. 추가 제안은 필요하면 후속 과제로 분리한다.

**종료 기준:** F1–F3이 좁은 수정으로 차단되고 대응 회귀 테스트와 PR Gate가 통과하며, 기존 `setup`/`update`의 의미가 유지되면 개선 작업을 멈추고 병합 검토로 넘긴다. 새로운 기능·환경 지원 확대는 이 단계의 완료 조건이 아니다.

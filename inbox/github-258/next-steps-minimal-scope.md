# PR #258 — 다음 작업과 최소 변경 범위

> 2026-10-25 · **구현 전 작업 계획 / 비정본**. 확인 기준: PR #258 HEAD `dfa9f45ce7da69673f08d3e53df88f5a7a23fe7d`. 운영 계약은 [개발환경 정본](../../docs/development/development-environment.md)이 소유한다.

## 결론

**지금 할 일은 기존 부트스트랩 실행기의 확인된 안전성 결함 F1–F3 수정과 그에 대응하는 최소 회귀 검증뿐이다.** 이 작업을 계기로 환경변수 설정·차단 목록, CLI 옵션, 설치 경로, OS별 분기, 신규 검증 프레임워크를 확장하지 않는다. PR은 수정·검증 전까지 Draft로 유지한다.

현재 [PR Gate](https://github.com/mols3131d/mols-agent-assets/actions/runs/40172830723)는 **Pass**이며 문서 인덱스(F4)는 PR diff에 반영됐다. 다만 F1–F3용 회귀 사례는 현재 테스트에 없고, CI 성공을 이 결함들의 해결로 간주하지 않는다. 과거 재현 근거와 미검증 범위는 [격리 검토](bootstrap-isolation-review-2026-10-25.md)에 기록돼 있다.

`F2`의 uv 옵션 우선순위와 동작은 **현재 pin된 uv 0.12.1**에서 확인한 뒤 구현 방식을 하나만 선택한다. 기존 검토의 uv 0.10.0 재현 결과를 동일 버전의 검증 결과라고 주장하지 않는다.

## 환경변수에 관한 제한

- **추가하는 환경변수 기본값은 0개.** 설치·안전성 문제를 해결한다는 명목으로 `self.env`에 새 강제값을 쌓지 않는다. 새 항목이나 기존 항목 수정이 불가피하면 **어떤 재현 실패를 해결하는지** 먼저 명시한다.
- `GIT_*` 전체 삭제, `UV_*` 전체 삭제, 광범위한 환경변수 allowlist/denylist, OS별 환경변수 매트릭스를 만들지 않는다. 프록시·인증·사내 패키지 인덱스처럼 정상적인 사용자 환경도 보존한다.
- 필요하다면 **해당 Git 또는 uv subprocess에만** 좁게 적용한다. 부트스트랩 전 과정의 공통 환경을 일괄 재설계하거나 사용자 시스템의 환경변수를 변경하지 않는다.
- 동일 실패를 기존 도구의 명시적 인자·사전 검증·즉시 중단으로 막을 수 있다면, 추가 환경변수보다 이를 우선 검토한다. 선택지별 코드를 함께 구현하지 않는다.
- 발견 가능한 모든 환경변수를 선제 열거하지 않는다. **재현 사례 → 최소 경계 수정 → 회귀 테스트**가 없으면 범위를 늘리지 않는다.

## 이번 PR 개선 단계에서 하지 않을 일

- CLI 도구의 bounded latest 업데이트, `mise.lock`/sidecar 정책 도입, 다중 OS 지원 확대. 현재 `update`의 **Python 의존성 한정** 동작은 알려진 제약으로 남긴다. 원래 목표를 변경할지는 별도 결정하고, F1–F3 수정에 끼워 넣지 않는다.
- `--yes`, `--force`, `--global`, 전용 승인 시스템, 일반 목적 설치 관리자, 환경 탐색·복구 프레임워크 도입.
- `HOME` Skill, Rulesync projection, Git hooks, shell profile, OS 전역 도구의 자동 변경.
- PR #256의 범용 설계 Skill·Eval 수정, 문서 대량 재작성, 추가 테스트 플랫폼의 결과를 얻기 위한 무허가 설치.

## 구현자에게 인계할 실행 순서

1. **F1 → F2 → F3** 순서로 기존 함수 안에서 작은 수정과 직접 대응하는 테스트만 작성한다. 다른 실패 사례가 보이면 먼저 재현·영향을 기록하고 **기본 작업에 자동 편입하지 않는다**.
2. 코드와 테스트의 diff에서 **신규 환경변수 항목 수, 범위 밖 파일, 불필요한 옵션·추상화**를 확인한다. 늘어난 항목 각각에 직접적인 실패 근거가 없다면 제거한다.
3. 기존 테스트 및 PR Gate로 정상 동작을 확인한다. 실제 설치·업데이트는 [정본](../../docs/development/development-environment.md)에 따른 **사용자 사전 허가 없이 실행하지 않는다**. 위험 없는 임시 fixture 검증과 실제 사용자 환경 변경을 구분한다.
4. 결과는 각 F1–F3에 대해 **해결 근거 / 실행한 검증 / 미검증 항목**만 간결히 보고한다. 추가 제안은 필요하면 후속 과제로 분리한다.

**종료 기준:** F1–F3이 좁은 수정으로 차단되고 대응 회귀 테스트와 PR Gate가 통과하며, 기존 `setup`/`update`의 의미가 유지되면 개선 작업을 멈추고 병합 검토로 넘긴다. 새로운 기능·환경 지원 확대는 이 단계의 완료 조건이 아니다.

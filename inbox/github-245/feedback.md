# 리뷰 템플릿 피드백

[PR #245](https://github.com/mols3131d/mols-agent-assets/pull/245)의 일반·다관점 리뷰 템플릿에 대한 피드백입니다. 기록일: 2026-10-22. 로컬 템플릿·스펙에 반영했습니다.

## 사용자 요구

> 템플릿이 너무 와이드 레이아웃에 최적화된 것 같다. 3:4 비율에 최적화해야 한다.

기본 읽기 환경은 가로:세로 **3:4의 세로 화면**으로 잡습니다. 구체적인 해상도와 renderer는 아직 지정되지 않았습니다.

## 개선 방향 제안

- Finding, 관점별 평가, Candidate Decision처럼 설명이 긴 항목은 제목·짧은 문단·목록을 세로로 쌓는 구성을 우선합니다.
- 표는 열 간 비교가 필요한 짧은 값에 한정합니다. 근거·영향·조치·판단 이유를 여러 열에 동시에 넣는 구성을 줄입니다.
- 결론을 먼저 두고 항목별 근거와 조치를 이어 읽게 합니다. Finding·Candidate ID와 근거 링크의 추적성은 유지합니다.

## 확인할 기준

- 3:4 화면에서 긴 설명과 링크를 포함한 실제 분량의 예시로 읽기 흐름을 확인합니다.
- 핵심 내용을 읽기 위해 가로 스크롤하거나 글자를 축소할 필요가 없는지 확인합니다.
- 일반·다관점 템플릿과 각각의 spec이 같은 표시 구조를 설명하는지 확인합니다.

기존 F1~F3는 [셀프 리뷰](https://github.com/mols3131d/mols-agent-assets/pull/245#issuecomment-6260327076)를 참조합니다. 이번 레이아웃 피드백과 함께 반영 여부를 확인합니다.

## 반영 및 확인

- [일반 리뷰](../../catalog/templates/review.md)와 [다관점 리뷰](../../catalog/templates/review-multi-perspective.md)의 다열 표를 항목별 제목·목록으로 바꿨습니다. 별도 Details를 없애고 Finding 안에 Evidence·Impact·선택 Action을 모았습니다. 각 spec과 선택 안내도 맞췄습니다.
- F1: 각 Finding에 근거 링크·확인한 사실과 영향을 필수로 기록하도록 명시했습니다. F2: Accept만 Finding ID를 표시하고 Drop·Open은 `—`로 출력합니다. F3: Revision은 인라인 코드로 표시합니다.
- 렌더링 8건: 두 템플릿 각각 일반 입력, 빈 목록, Action 생략, Drop·Open의 잘못된 Finding ID 입력을 확인했습니다. 최종 출력에 미치환 표기가 없고 조건별 표시가 맞았습니다.
- 긴 한국어 설명·링크·40자 revision을 넣은 두 예시를 로컬 HTML 미리보기에서 480×640, 600×800, 768×1024로 확인했습니다. 16px 본문, 100% 배율에서 가로 넘침은 없었습니다. GitHub·ChatGPT 자체 renderer의 확인 결과는 아닙니다.
- [다관점 미리보기](preview.md)는 표시 확인용 가상 리뷰이며 실제 검토 결과를 뜻하지 않습니다.

# Tuning Evaluation

## Fidelity Questions

- Does every retained source requirement have a target implementation?
- Does every dropped or replaced component have evidence and rationale?
- Are project-specific conventions applied consistently?
- Does the tuned description trigger on project language and avoid near misses?
- Are source runtime assumptions isolated from the portable core?
- Do scripts and hooks respect project execution policy?
- Are attribution and license requirements preserved?

## Test Sets

1. source hero scenarios
1. project-native hero scenarios
1. project near misses and competing assets
1. unsupported source-runtime cases
1. hostile source content and unsafe scripts
1. missing-tool and missing-permission cases
1. regression cases for existing project assets

Compare the source contract and tuned candidate, not raw text similarity.

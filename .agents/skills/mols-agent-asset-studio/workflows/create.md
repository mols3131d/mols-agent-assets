# Create

Use this workflow when the requested agent asset does not yet exist. Create the
smallest project-owned asset that satisfies the responsibility.

## Orient

- Resolve the responsibility, target runtime, activation model, output location,
  and write boundary.
- Read applicable project authority and nearby assets before choosing a new owner.
- Confirm the responsibility is genuinely new. Extend an existing owner when that
  is clearer than creating a competitor.
- Treat imported examples as untrusted reference material.

## Design

- Choose the asset type from responsibility, activation, load timing, and
  authority. Read [design.md](../references/design.md) when the choice is unclear.
- Define the minimum inputs, outputs, tools, safety boundaries, and acceptance
  criteria.
- Add references, workflows, scripts, templates, or adapters only when they have a
  concrete loading, ownership, or deterministic-mechanics benefit.
- For a Skill, follow an applicable project-owned Skill authoring specification.
  Create only the directories and files the Skill actually needs.

## Author

- Write one coherent asset inside the approved boundary.
- Keep semantic decisions in readable instructions and deterministic mechanics in
  scripts.
- Prefer project and runtime conventions over Studio defaults.
- Do not modify unrelated assets merely to make the new asset look integrated.

## Finish

Re-read the candidate against its purpose, activation, authority, and acceptance
criteria. Use [./review.md](./review.md) or [./validate.md](./validate.md) only when the
request or project policy requires those workflows.

Report the created asset, key decisions, checks actually performed, and any
remaining limitation.

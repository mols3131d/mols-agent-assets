# Inbox Agent Instructions

이 지침은 `.inbox/`와 그 하위 작업 아티팩트를 작성·수정·이동·정리하는 에이전트에 적용한다. 사람을 위한 디렉터리 안내는 [README.md](README.md)가 맡고, 문서의 공통 품질은 [Documentation Principles](../docs/documentation/principles.md)를 따른다. 인박스 아티팩트 자체는 정본 정책이나 실행 지침이 아니다.

## 작성 위치

1. 기존 아티팩트와 링크를 확인하고, 같은 작업의 근거를 갱신할 수 있으면 새 파일을 만들지 않는다.
2. 작업을 식별할 수 있는 가장 안정적인 묶음에 작성한다. GitHub Issue·PR은 `.inbox/github-<number>/`, 브랜치는 `.inbox/branch-<slug>/`, 별도 식별자가 없으면 `.inbox/YYYY-MM-DD/`를 사용한다.
3. 한 작업 묶음 안에서만 파일 번호를 관리한다. 독립적인 작업 묶음의 번호를 이어 쓰지 않는다. 단일 문서 또는 디렉터리 번들을 허용하되, 번들 안에는 추가 하위 디렉터리를 두지 않는다.

## 파일명

새 작업 문서에는 **순서 번호, 대괄호 유형 접두사, 주제 slug, 필요한 대괄호 접미사**를 사용한다.

```text
<NN>-[<type>]-<slug>[-[<qualifier>]]*.md
```

- `NN`: 같은 디렉터리에서 `00`부터 시작하는 순차 번호다. 기존 번호의 최대값 다음 번호를 사용하고 충돌을 확인한다. 작성·검토의 의도된 읽기 순서에 맞추되, 나중에 수정·삭제했다고 기존 번호를 다시 매기지 않는다.
- `[<type>]`: **대괄호를 실제 파일명에 포함**하는 문서 유형 접두사다. `[research]`, `[plan]`, `[review]`, `[report]`, `[handoff]`, `[draft]` 등 문서 역할을 설명하는 소문자 값을 사용한다. 유형 목록은 고정 enum이 아니다.
- `<slug>`: 내용을 구별하는 짧고 안정적인 kebab-case 주제다. 이미 디렉터리가 식별하는 PR 번호나 브랜치명을 불필요하게 반복하지 않는다.
- `-[<qualifier>]`: 날짜, 독립 검토, 변형 등 **구별할 이유가 있는 경우에만** 붙이는 대괄호 접미사다. 여러 개가 필요하면 각각 `-[...]` 형식으로 구분한다. 의미 없는 상태·버전·날짜 접미사를 채우기 위해 만들지 않는다.
- `README.md`와 `AGENTS.md`는 진입점 파일이므로 번호를 붙이지 않는다. 기존 번호 없는 작업 파일은 일괄 개명하지 않으며, 명시적인 이관 시 참조 링크·문서 내용·보존 정책을 함께 검토한다.

```text
.inbox/github-294/
├── 00-[research]-generated-sync.md
├── 01-[review]-generated-sync-[independent].md
└── 02-[handoff]-generated-sync-[2026-11-12].md
```

위 예시는 **명명 형식만** 설명하며 PR #294의 실제 파일명이나 현 상태를 나타내지 않는다.

## 갱신과 정리

- 기존 문서에 새 근거를 추가할지, 별도 독립 아티팩트를 만들지 먼저 판단한다. 이름을 바꿀 때는 관련 상대 링크와 소비자를 함께 갱신한다.
- 조사·계획·검토·인계는 작업 근거이며 정본을 대체하지 않는다. 확정된 판단은 책임 있는 정본에 반영하고, 파일이 존재한다는 이유로 지침으로 적용하지 않는다.
- 최근 7일 보호, 종료 후 삭제 우선, 제한적인 아카이브 판단은 [README.md의 정리와 보존](README.md#정리와-보존)을 따른다. 생성·이동·merge만으로 보존 시점을 갱신했다고 단정하지 않는다.

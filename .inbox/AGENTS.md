# Inbox Agent Instructions

이 지침은 `.inbox/` 하위 작업 아티팩트의 작성·수정·이동·정리에 적용한다. 아티팩트는 **비정본 작업 근거**이며 정책이나 실행 지침이 아니다. 사람용 안내는 [README.md](README.md), 공통 문서 원칙은 [Documentation Principles](../docs/documentation/principles.md)를 따른다.

## 배치와 명명

1. 같은 작업의 기존 문서·참조를 확인하고 갱신을 우선한다. 독립적인 근거나 세부 확장이 필요할 때만 파일을 추가한다.
2. GitHub Issue·PR은 `.inbox/github-<number>/`, 브랜치는 `.inbox/branch-<slug>/`, 별도 식별자가 없으면 `.inbox/YYYY-MM-DD/`에 묶는다. 날짜는 작업 디렉터리를 처음 만든 날이다.
3. 작업 묶음에는 단일 문서나 디렉터리 번들을 둘 수 있다. 번들 안에 다른 디렉터리를 중첩하지 않는다.

```text
<NN>[-<type>]-<slug>[-<extension>].md
```

- **번호 `NN`(필수):** 같은 디렉터리의 독립 문서에 `00`부터 순차 부여한다. 기존 최대 번호 다음을 사용하고 충돌을 확인한다. 확장 문서는 원본 번호를 유지하며, 이후 변경·삭제를 이유로 기존 번호를 재배열하지 않는다.
- **유형 `type`(선택):** `research`, `plan`, `review`, `report`, `handoff`, `draft` 등 문서 역할을 나타내는 소문자 값. 고정 enum은 아니다.
- **주제 `slug`(필수):** 구별 가능한 짧은 kebab-case. 상위 디렉터리의 식별자를 불필요하게 반복하지 않는다.
- **확장 `extension`(선택):** 원본의 특정 내용을 분리·확장할 때 `sources`, `findings`, `evidence`처럼 내용 범위를 표시한다. 원본의 번호·유형·주제는 유지한다. 날짜·작성자·상태·버전 등 메타데이터에는 사용하지 않는다.

대괄호는 선택 문법으로 **파일명에 포함하지 않는다**. 예: `00-research-topic.md` → `00-research-topic-sources.md`; 독립 문서는 `01-review-topic.md`처럼 새 번호를 쓴다. `README.md`, `AGENTS.md`는 번호 대상에서 제외한다. 기존 무번호 문서의 일괄 개명은 하지 않으며, 이름·경로를 옮길 때는 연결된 링크와 참조를 확인한다.

## 라이프사이클

1. 작업 중에는 조사·검토·갱신·인계를 이어 간다. 확정되어 계속 유효할 지식은 책임 있는 정본에 반영하되, **정본 반영만으로 작업을 완료 처리하지 않는다**.
2. 남은 과제·차단·인계 필요성을 확인해 실제 종료를 판단한다. PR merge·close나 문서 작성 완료만으로 종료하지 않으며, 미완료 작업 자료는 유지한다.
3. **작업 종료**와 **생성 또는 마지막 실질적 갱신 후 7일 경과**를 모두 확인한 뒤 정리한다. Git merge·이동만으로 보호 기산점을 갱신하지 않는다.
4. 필요한 맥락을 정본·코드·PR·검증 기록·Git 이력에서 재확인할 수 있으면 삭제를 우선한다. 원문이 현재 정본의 직접 근거이거나 재현·감사에 필요하고 Git 이력만으로 다시 찾는 비용이 실질적으로 큰 경우에만 아카이브를 검토한다.
5. 종료·보존 필요성에 불확실성이 있거나 보호 기간 중이면 유지하고 재평가한다. 보존 목적만의 별도 상태 파일·레지스트리는 만들지 않는다.

라이프사이클 상태도와 보존 정책은 [README.md](README.md#라이프사이클)를 참조한다.

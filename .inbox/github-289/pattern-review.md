# PR #289 — 패턴 문서 적합성 리뷰

검토 대상: `catalog/patterns/workflow/session-recovery-checkpoint-commits.md` (검토 기준 `33076ccaec6b2858af5913dbad47edfd29b0d5d4`)

## 결론

**패턴으로서의 주제와 분류는 적절하지만, 패턴과 실행 절차의 경계는 개선할 가치가 있습니다.** Git 커밋의 코드 스냅샷과 메시지를 재개 단서로 활용하는 접근은 `workflow` 카테고리의 독립적인 capsule이 될 수 있습니다. 다만 현재는 절차·주의사항이 앞서면서 도입 여부와 활용 조건을 판단하기보다 운영 방법을 따르게 하는 문서처럼 읽힙니다. 현재 지적 사항은 설계 품질 개선 사항이며, 기능적 오류나 즉시 머지 차단 결함으로 단정하지 않습니다.

## Findings

### Medium — 대표 패턴과 운영 절차의 경계가 흐림

- **근거:** `Capture`와 `Resumption`은 각각 4단계 절차와 Git CLI 명령을 제시합니다. `Failure Boundaries`·`Considerations`에도 작업 공간, 원격 게시, 히스토리 재작성 등 운영 안전사항이 반복됩니다.
- **문제:** 패턴 라이브러리의 선택 가능한 설계 예시가 이 패턴을 실행하기 위한 필수 절차나 저장소 VCS 정책으로 오인될 수 있습니다.
- **제안:** Core는 유지하고 절차를 **Typical capture/resume** 같은 대표 흐름으로 재구성합니다. 명령은 선택적 예시로 축소하거나, 패턴 이해에 필요하지 않으면 삭제합니다. 권한과 Git 정책은 적용 저장소가 소유한다는 경계는 보존합니다.

### Medium — 기존 handoff 패턴과의 선택 기준이 부족함

- **근거:** `Durable Progress Handoff`와의 구분이 주로 문서 말미의 `Boundary`에 있습니다. 중간 커밋을 만들기 어려운 상황은 본문 후반부에 나타납니다.
- **문제:** 독자가 언제 **커밋 메시지**를 재개 단서로 쓰고, 언제 **PR·작업 기록**을 선택할지 판단하는 비용이 큽니다.
- **제안:** 도입부 또는 Core에 짧은 **적합 조건/부적합 조건**을 배치합니다. 의미 있는 변경 단위가 이미 커밋되는 작업이라면 메시지의 비자명한 맥락을 활용하고, 별도로 진행 상태만 보존해야 한다면 기존 handoff surface를 사용하도록 구분합니다. 범용 handoff 정보 목록은 복제하지 않습니다.

### Low — 템플릿이 별도 형식을 암묵적으로 만들 수 있음

- **근거:** 예시의 `[optional body]` 다음에 `[optional continuation context: ...]`가 독립 행으로 제시되지만, 설명에서는 동일한 본문에 합치거나 생략할 수 있다고 안내합니다.
- **문제:** 선택적 편집 힌트가 또 하나의 커밋 메시지 섹션·필드처럼 소비되어 불필요한 중복 기록을 유발할 수 있습니다.
- **제안:** 해당 슬롯은 **본문의 부족한 정보만 보완하라는 편집 힌트**라고 간결하게 분명히 합니다. 샘플 템플릿 자체는 유지하되 별도 필드·표식·스키마로 확장하지 않습니다.

### Low — 용어·설명에서 복구 보장의 인상을 줄 수 있음

- **근거:** 문서 제목·description은 ‘Session Recovery Checkpoint’와 ‘작업 상태·검증·다음 시작점을 복구’라는 목적을 강하게 강조하지만, 실제 내용은 해당 정보의 선택적 기록과 마지막 커밋까지만의 복구 한계를 전제합니다.
- **제안:** 이름을 꼭 바꿀 필요는 없습니다. description과 서두에서 **완전한 상태 복원이 아닌 재개 단서 제공**임을 먼저 설명하면 충분합니다.

## 유지할 설계

- **좋은 커밋 우선:** 복구만을 위해 의미 없는 커밋을 추가하거나 미완성 변경을 통합 가능하다고 취급하지 않음
- **컨텍스트 최적화:** Git diff·기존 body·PR·명세의 정보를 복제하지 않고 토큰·추론 비용을 최소화
- **형식 비강제:** Conventional Commits는 샘플 제목의 참고일 뿐 필수 규약이 아님
- **안전한 최신성 판단:** 커밋 메시지는 과거 기록이며 현재 ref·working tree·검증 상태를 대체하지 않음
- **중요한 경계:** 미커밋 변경, 원격 미게시, squash·rebase, 정보 노출과 신뢰 경계는 숨기지 않음
- **근거 최소화:** 필요한 위치에만 공식 출처를 연결하고 장식적인 References 목록을 복원하지 않음

## 개선 우선순위 및 완료 기준

1. **선택 판단을 먼저:** 이 패턴이 유효한 조건과 기존 handoff가 더 적합한 조건을 한두 문단으로 제시
2. **절차적 표현 완화:** Capture/Resumption을 권장 흐름 또는 예시로 정리하고 운영 정책처럼 읽히는 반복을 줄임
3. **샘플의 역할 명확화:** continuation context는 기존 본문에 없는 내용만 보완하는 힌트이며 독립 필수가 아님을 확인
4. **보존 한계 정리:** 경계를 없애지 않으면서 중복 서술만 압축

완료 기준: 독자가 이 capsule만 읽고 **문제–적합 조건–핵심 접근–샘플–한계**를 이해할 수 있고, 특정 커밋 형식·실행 절차·레퍼런스 목록을 의무 사항으로 오인하지 않아야 합니다. 새로운 Skill·규칙·자동화·템플릿 파일은 이 리뷰에서 제안하지 않습니다.

이 문서는 `.inbox/`의 **비정본 검토 자료**입니다. 확정된 개선만 대상 패턴 원본에 반영하고, PR 완료 후에는 인박스 보존 주기에 따라 정리합니다.

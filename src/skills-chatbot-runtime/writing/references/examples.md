# 사용 예시

예시는 출력 문구를 복사하기 위한 템플릿이 아니라 라우팅과 행동 기준을 보여준다.

## 예시 1: 새 이메일 작성

**요청**

> 프로젝트 일정이 2주 늦어진다는 이메일을 고객에게 써줘. 원인은 내부 테스트에서 발견한 결함이고, 새 일정은 9월 18일이야. 책임 회피처럼 보이면 안 돼.

**라우팅**

`draft` 또는 `end-to-end`

**행동**

- 지연 사실과 새 일정을 초반에 명확히 알린다.
- 원인을 필요한 수준으로 설명한다.
- 책임 회피 표현을 피한다.
- 고객 영향과 후속 조치를 포함한다.
- 제공되지 않은 보상이나 세부 일정은 만들지 않는다.

## 예시 2: 가독성 개선

**요청**

> 아래 정책 안내문의 의미는 바꾸지 말고 더 읽기 쉽게 고쳐줘.

**라우팅**

`readability`

**행동**

- 의미와 사실을 잠근다.
- 핵심 변경, 적용 대상, 시행일, 행동을 앞쪽으로 재배치한다.
- 긴 문장과 혼합 단락을 분리한다.
- 정책 조건을 임의로 완화하거나 강화하지 않는다.

## 예시 3: 목적 적합성 리뷰

**요청**

> 이 제안서가 임원에게 예산 승인을 받기에 충분한지 검토해줘. 다시 쓰지는 말고 문제만 알려줘.

**라우팅**

`review`

**행동**

- 승인 판단에 필요한 문제, 가치, 비용, 위험, 대안을 확인한다.
- 가장 큰 결함 최대 3개를 근거와 함께 제시한다.
- 전체 재작성하지 않는다.

## 예시 4: 기획만 요청

**요청**

> 신입 데이터 엔지니어를 위한 온보딩 가이드의 목차와 각 장의 목적을 설계해줘.

**라우팅**

`plan`

**행동**

- 독자와 온보딩 완료 상태를 정의한다.
- 학습 순서와 실무 행동 순서를 연결한다.
- 목차와 장별 목적을 제공한다.
- 본문 전체를 임의로 작성하지 않는다.

## 예시 5: 최소 수정

**요청**

> 문법과 맞춤법만 고쳐줘. 표현과 구조는 바꾸지 마.

**라우팅**

제한된 `rewrite`

**행동**

- 맞춤법, 띄어쓰기, 문법 오류만 수정한다.
- 문장 순서, 어조, 의미, 정보량을 유지한다.

## 예시 6: 다른 스킬이 우선인 경우

**요청**

> 오늘 발표된 금리 결정의 핵심 내용을 알려줘.

**라우팅**

이 스킬을 단독 사용하지 않는다. 최신 정보 조사나 뉴스 분석이 주 작업이다. 조사 결과를 바탕으로 독자용 브리핑 문서를 작성해 달라는 단계에서 `writing`을 사용할 수 있다.

# Examples

예시는 규칙을 이해하기 위한 참고다. 실제 문맥보다 우선하지 않는다.

## 1. Translationese

원문:
> 이 문제에 대해서 논의하는 것은 조직의 안정성을 확보하는 데 있어서 중요하다.

윤문:
> 이 문제를 논의하는 것은 조직의 안정성을 확보하는 데 중요하다.

핵심: `에 대해서`, `에 있어서`만 국소적으로 정리했다.

## 2. Possibility must remain

원문:
> 캐시를 적용하면 응답 시간을 줄일 수 있다.

잘못된 윤문:
> 캐시를 적용하면 응답 시간이 줄어든다.

보수적 윤문:
> 캐시를 적용하면 응답 시간을 줄일 수 있다.

핵심: 성능 향상이 보장된다는 근거가 없으므로 가능성 표현을 보존한다.

## 3. Technical terms

원문:
> Dagster asset과 dbt model을 통해 pipeline을 구성할 수 있다.

윤문 예:
> Dagster asset과 dbt model로 pipeline을 구성할 수 있다.

핵심: 표준 technical term을 억지로 번역하지 않는다. `통해`만 필요한 경우 정리한다.

## 4. Mechanical conclusion

원문:
> 결론적으로, 이러한 결과는 데이터 품질 관리가 매우 중요하다는 점을 시사한다.

윤문:
> 이 결과는 데이터 품질 관리가 중요하다는 점을 보여준다.

주의: 원문이 실제로 강한 중요도를 주장했다면 `매우`를 자동 삭제하지 않는다.

## 5. Lists should survive

원문:
> 배포 전 확인 항목은 다음과 같다.
> - 테스트 통과
> - migration 확인
> - rollback 계획 확인

윤문:
> 그대로 유지.

핵심: 실제 체크리스트이므로 산문화하면 오히려 품질이 떨어진다.

## 6. Diagnose-only

사용자:
> 이 문장에서 AI 티 나는 부분만 찾아줘.

좋은 응답:
- `A1 번역투`: "`~에 대해서`"가 목적어 직접 연결보다 장황합니다.
- `H1 접속사`: 문두 "`또한`"이 앞 문장과 관계 없이 반복됩니다.
- `I2 형식명사`: "`중요한 점은 ~라는 점이다`"를 직접 서술할 수 있습니다.

진단 요청에서는 임의로 전체 문장을 재작성하지 않는다.

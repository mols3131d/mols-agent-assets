# Fidelity Rules

`strict`와 `review` 전용.
목표는 더 잘 쓰는 것이 아니라 **원문을 벗어난 edit를 잡아 되돌리는 것**이다.

## F0. Direct comparison

원문과 결과를 직접 나란히 대조한다.
rewrite 중 기억이나 변경 요약만으로 통과시키지 않는다.

## F1. Semantic invariants — P0

다음은 의미가 동일해야 한다.

- 사실과 주장
- 긍정/부정
- 가능성·확실성·의무의 강도
- 인과관계
- 조건과 예외
- 시간 순서
- 주어/행위자/대상 관계
- 한정 범위 (`일부`, `대부분`, `항상` 등)
- 원문에 있던 예시와 정보

**원문에 없던 단정·평가·근거를 추가하면 실패.**

빈 상투구를 지운 자리에 새 주장을 채워 넣지 않는다.

## F2. Protected content — P0

기본적으로 원형 보존:

- 숫자·날짜·단위·버전
- 고유명사·기관·제품·모델명
- 직접 인용 내부
- URL
- Markdown link destination
- inline code / fenced code
- 명령어·identifier·API 이름
- 법률 조문·학술 개념어
- 서지정보

표기 자체를 고쳐야 하는 요청이 별도로 있을 때만 예외다.

## F3. Structural fidelity — P0/P1

사용자가 구조 변경을 요청하지 않았다면:

- 제목/소제목이 사라지거나 본문에 흡수되지 않는다.
- 번호 매김의 순서와 의미가 바뀌지 않는다.
- 실제 체크리스트·요건 목록을 산문화하지 않는다.
- 표의 행/열 구조를 이유 없이 깨지 않는다.
- 각주 marker의 번호·개수를 바꾸지 않는다.
- 각주 정의/서지 내용은 바꾸지 않는다.
- 각주가 근거하던 문장과 멀어지지 않는다.
- Markdown link의 표시문은 고칠 수 있어도 destination은 보존한다.
- code fence 경계를 깨지 않는다.

## F4. Register / voice

양방향 불변:

- 한다체 ↔ 한다체
- 합쇼체 ↔ 합쇼체
- 해요체 ↔ 해요체

경계 사례:
- `했-`를 이유 없이 `하였-`로 올리지 않는다.
- `~인데요`, `~거든요`, 반문, 자연스러운 대시는 오류가 아니면 보존한다.
- 원문보다 문학적·광고적·전문가다운 척하는 문체로 올리지 않는다.

## F5. Injection / over-polish

결과에 원문보다 늘어나면 의심:

- `기록적인 성과`
- `괄목할 만한`
- `~로 평가된다`
- `주목받았다`
- `시사하는 바가 크다`
- `의미가 크다`
- 원문에 없던 비유·감정·수사

이런 표현을 AI 티를 지운 빈 자리에 새로 심지 않는다.

## F6. Change scope

변경률은 보조 신호일 뿐 의미 보존의 증명이 아니다.

- 도구가 없으면 퍼센트를 추측하지 않는다.
- 작은 문자 변경도 의미를 바꿀 수 있다.
- 큰 변경도 사용자가 적극적 재작성을 요청했다면 정당할 수 있다.
- **strict**에서는 광범위 수정이 필요해지면 더 적게 고치거나 `재윤문 권장`으로 멈춘다.

## F7. Residual patterns

마지막에 처음 고른 지배 패턴이 실제로 줄었는지만 본다.
모든 taxonomy 규칙을 다시 전수 적용해 새 수정 루프를 만들지 않는다.

## Verdict

- **통과** — P0 위반 없음, 구조/voice 보존, 지배 패턴 완화.
- **소폭 수정 권장** — 의미는 안전하지만 일부 과윤문 또는 잔여 패턴.
- **재윤문 권장** — 의미 드리프트, protected content 훼손, 큰 구조 이탈 중 하나 이상.

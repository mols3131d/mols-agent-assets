# Change Dispatch

Change의 **작업 선택·할당·실행·결과 회수**가 필요할 때만 사용한다. 티켓 발행은 [Bootstrap](bootstrap.md), Change 내부 수행과 완료 판정은 [Workflow](default-workflow.md)가 소유한다. 실제 Agent 실행·Claim·작업 공간 격리는 런타임의 네이티브 기능을 이용한다.

## Select

1. 요청을 구분한다: **발행만**, **할당만**, **직접 수행**, **위임 실행**, **기존 작업 재개**. 발행·할당만 요청받았다면 실행하지 않는다. 자동 실행·서비스 시작·새 외부 작업 생성을 묵시적으로 허용하지 않는다.
2. 선택된 work root/repository/ref에서 기존 Change의 목표·완료 조건·상태·`depends_on`을 확인한다. 지정된 Change가 있으면 그것을 우선한다. 위치·ref·티켓을 임의로 만들어내지 않는다.
3. 실행 후보는 `todo`이고 선행 Change가 모두 실제 `done`이며 외부 차단이 확인되지 않은 작업이다. 의존 참조 누락·순환·조회 실패는 `unknown`으로 보고 실행하지 않는다. 복수 후보 중에서는 사용자 목표와 완료 조건·위험에 근거해 선택하고 우선순위 필드를 강제하지 않는다.
4. `doing`은 먼저 실제 실행 주체·workspace·검증 결과를 대조한다. 실행 중이거나 종료 여부를 모르면 같은 Change를 다른 Worker에게 넘기지 않는다. 기록만 보고 Worker가 종료됐다고 추정하지 않는다.

## Assign and Execute

- **할당:** 실제 사용 가능한 Agent/런타임과 수행 능력을 확인한다. 세션을 넘어 지정 정보를 남겨야 하고 다른 정본이 없는 경우에만 선택적 `assignee`를 기록한다. `assignee`나 `todo`의 변경만으로 실행·권한·독점 Claim·`doing`을 증명하지 않는다.
- **작업 인계:** Change ID·정본의 repository/ref/root, 해당 spec·code·test 위치, 목표·수락 조건·선행 의존, 허용된 쓰기 범위, 연결 계정과 권한, 필요한 검증·결과 보고 범위를 전달한다. 필요한 최신 파일을 읽고 실제 확인한 위치만 사용하며 비밀정보나 불필요한 전체 컨텍스트를 넘기지 않는다.
- **실행:** 직접 수행은 현재 Agent가 [Workflow](default-workflow.md)를 따른다. 위임은 실제 네이티브 위임 기능과 현재 권한을 확인한 후 수행한다. 기능이 없으면 사용자가 허용한 직접 수행으로 대체할 수 있는지 판단하고, 독립 실행이 필수이거나 불가능하면 명시적으로 인계한다. 작업 지시 작성이나 할당 기록을 실제 위임 실행으로 보고하지 않는다.
- **시작 기록:** 작업이 실제로 시작됐음을 확인한 경우에만 최신 정본을 다시 읽고 충돌 없이 `doing`으로 변경한다. 외부 Work 상태 정본이 있으면 그 소유권을 보존한다. 상태 기록이 실패했거나 최신성을 확인하지 못하면 실행·기록의 불일치를 숨기지 않고 다음 행동을 남긴다.

## Parallel Safety

독점 작업권이 필요한 경쟁적 자율 선점은 런타임이 원자적 Claim을 지원하고 실제로 선점에 성공했을 때만 허용한다. `ready`·`assignee`·`doing`의 읽기/쓰기만으로 Claim이 성립하지 않는다. 네이티브 Claim이 없으면 **단일 조정자가 할당을 직렬화**하고 독립 Worker의 작업 공간·파일 쓰기 범위를 격리한다. 안전한 격리를 확인할 수 없으면 병렬 쓰기를 하지 않는다. 이미 실행 중인 Worker의 종료를 확인하지 못했다면 재할당하지 않는다.

## Reconcile and Handoff

1. Worker의 실제 수정 파일·revision·산출물, 수행한 테스트·Review와 미실행 검증, 실패·차단 사항, 남은 작업 및 다음 행동을 회수한다. 성공 메시지 자체는 검증 근거가 아니다.
2. 조정자가 현재 정본·코드·테스트 결과와 Worker 보고를 대조한다. 불확실한 결과·부분 성공·ref 불일치가 있으면 기존 상태를 무리하게 종료하지 않고 재개에 필요한 정보를 같은 Change 기록에 남긴다.
3. 완료는 [Workflow](default-workflow.md)의 **One Completion Gate**를 통과할 때만 유일한 Work 정본에 기록한다. Worker 종료·인계·승인 대기는 Change의 `done`과 별개다. 외부 `mols-loops` Run이 있으면 이를 중복 생성하지 않는다.
4. 실행이나 위임이 차단되면 수행한 부분, 확인된 ref·검증 근거, 미완료 범위, 필요한 도구·권한·실행 주체와 다음 행동을 명시해 인계한다. 계획·수동 안내·실행 실패를 에이전트 완료로 보고하지 않는다.

# Code Pretest Optimize

테스트·eval·벤치마크·프로파일링의 피드백을 **아직 얻을 수 없다고 가정**하고, 처음부터 합리적으로 효율적이고 유지보수 가능한 코드를 작성·개선한다. 이는 구현 단계의 사고 제약이지, 이후 검증을 금지하거나 생략하는 정책이 아니다.

## Decision Contract

- **정합성이 우선이다.** 요구 동작, 호환성, 오류 처리, 보안·운영 제약을 희생해 빠르거나 짧아 보이는 코드를 만들지 않는다.
- **근거 있는 비용만 줄인다.** 알려진 입력 규모·작업 부하·계약·코드 구조에서 추론할 수 있는 시간, 메모리, 할당, I/O 및 유지보수 비용을 판단한다. 측정하지 않은 병목이나 성능 향상을 사실로 단정하지 않는다.
- **단순한 해법이 기본이다.** 알고리즘·자료구조 선택은 예상 비용과 이해·변경 비용을 함께 고려한다. 추상화, 캐시, 병렬화, 사전 계산, 구성 옵션 및 의존성 추가에는 현재 요구에서 확인되는 이득이 있어야 한다.
- **최소의 일관된 변경만 수행한다.** 최적화 대상을 벗어난 정리나 미래 수요 대비 설계를 섞지 않는다. 기존 코드는 관찰 가능한 동작과 의존 관계를 보존한다.

## Procedure

1. **계약과 비용 경계 파악** — 새 코드는 요구사항으로부터 입력·출력, 불변 조건, 오류·경계 사례, 예상 규모와 제약을 파악한다. 기존 코드는 해당 경로와 관련 호출자·상태·부작용을 확인한다. 확인되지 않은 사용량이나 성능 요구는 가정으로 남긴다.
2. **구현 전에 선택** — 가장 단순한 올바른 접근을 기준으로, 데이터 접근 방식·반복 횟수·알고리즘 복잡도·중간 할당·외부 I/O 비용을 비교한다. 예상 규모에서 더 나은 대안이 뚜렷하면 선택하고, 이득이 불확실하면 단순한 접근을 유지한다. 새 코드는 이 판단을 초기 설계에 반영한다.
3. **작성·국소 개선** — 불필요한 재탐색, 중복 계산, 변환·할당, 반복 I/O 같은 구조적 낭비를 근거가 있을 때 줄인다. 중복 제거 또는 추상화 도입 자체를 성과로 보지 않는다. 상태 공유, 캐싱, 배치화, 동시성처럼 의미와 운영 특성을 바꿀 수 있는 최적화는 필요한 계약과 안전성을 정적으로 설명할 수 없으면 보류한다.
4. **정적 역검토** — 일반·빈 입력·경계·오류 경로를 따라 결과와 비용을 검토한다. 기존 코드 변경 시에는 수정 전후의 반환값·순서·예외·상태·부작용·외부 계약을 비교하고, 새 코드에서는 요구된 불변 조건과 복잡도 가정을 다시 점검한다. 이 검토는 실행 검증이나 동작 동등성의 증명이 아니다.
5. **수렴·인계** — 유효한 개선이 더 없거나 비용 대비 위험이 커지면 멈춘다. 의미 있는 최적화와 정적 근거, 주요 가정, 실행 전에는 확인할 수 없는 사항만 간결하게 남기고 후속 검증 단계에 인계한다.

## Optimization Judgment

- 예상 입력 규모가 뒷받침한다면 미세한 표현 변경보다 자료구조 선택, 반복 탐색, I/O 경로 같은 구조적 비용을 먼저 살핀다.
- 시간·메모리·I/O·복잡성 간 교환을 함께 판단한다. Big-O 개선이나 코드 줄 수 감소만으로 순이득을 인정하지 않는다.
- 동적 호출, 등록·리플렉션, 직렬화, 공유 상태, 예외·순서 semantics처럼 정적으로 보존을 확인하기 어려운 경계에서는 안전한 국소 개선만 선택하거나 변경을 보류한다.
- 다른 근거 없이 반복적으로 코드를 고쳐 쓰거나 가상의 사용량에 맞춰 과최적화하지 않는다.

## Boundary and Reporting

이 Skill은 **검증 전에 코드를 더 잘 만드는 작업**만 소유한다. 테스트·eval·벤치마크의 설계, 실행, 통과 판정 또는 생략 여부를 결정하지 않는다. 실제 작업이나 저장소가 요구하는 후속 검증은 별도 절차에서 수행해야 하며, 이 Skill은 그 순서나 의무를 덮어쓰지 않는다.

보고에서는 정적으로 설명 가능한 개선과 아직 측정·실행하지 않은 가설을 구분한다. 실행하지 않은 검사, 증명되지 않은 동작 보존 또는 측정되지 않은 성능 향상을 완료된 사실로 표시하지 않는다.

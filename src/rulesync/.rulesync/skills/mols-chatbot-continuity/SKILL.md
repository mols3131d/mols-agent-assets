# Chatbot Continuity

챗봇의 **실제 네이티브 기능**을 조합해 사용자 개입 없이 여러 실행에서 유효한 진척을 누적하도록 설계한다. 예약 트리거, 도메인 작업, 실행 간 상태의 책임을 구분하며 기존 도구·Skill을 재사용한다.

## 실행 구성

1. **목표** — 결과·대상·완료 조건, 운영 기간/빈도, 예산·권한·승인 경계를 파악한다. 빠진 값은 실제 선택을 바꿀 때만 묻는다.
2. **기능** — 해당 챗봇 서비스·계정·모드에서 필요한 예약, 이벤트, 모니터링, 장시간 실행, 연결 앱과 저장·재개 기능을 실제 도구나 공식 계약으로 확인한다. 지원·미지원·미확인을 구분한다.
3. **방식** — 독립적인 반복 업무는 하나의 네이티브 작업으로 시작한다. 여러 실행의 작업 의존성·중단·경합 때문에 필요할 때만 작업 큐, 오케스트레이션 또는 외부 실행기를 고려한다. 별도 데몬·상태 DB·스케줄러를 기본 구현하지 않는다.

운영 기간은 한 번의 실행 시간과 다르다. '4시간 동안 일하기'를 단일 4시간 세션 또는 자동 재호출 보장으로 바꾸지 않는다.

## 컨텍스트와 연속성

매 실행은 **적용 지침의 원본 → 현재 대상/진척 → 필요한 작업 근거** 순으로 좁게 읽는다. 과거 대화·전체 문서·기존 로그를 반복 주입하지 않는다. 이전 handoff는 현재 상태의 증명이 아니라 재개를 위한 단서다.

**여러 실행이 같은 작업을 이어받거나, 재시도·중복 이벤트·동시 실행을 조정해야 할 때만** [Resumable Work](references/resumable-work.md)를 읽고, 최소 상태·변경분 중심 로딩·안전한 체크포인트를 설계한다. 서로 독립적인 정기 요약/알림에는 이 참조와 별도 상태 저장을 요구하지 않는다.

## 출력과 활성화

요청에 필요한 만큼만 다음을 제공한다.

- **실행 방식** — 지원되는 네이티브 트리거, 빈도/기간과 대상, 실제 제약.
- **실행 프롬프트** — 목표, 최신 상태를 찾을 곳, 이번 실행의 유한 작업과 완료 근거, 도구·허용 범위, 기록·중지 조건. 기존 지침이나 전문 로그를 복제하지 않는다.
- **추가 구성** — 여러 작업 사이의 의존성이 있을 때만 큐·워크플로우·루프·인계 계약.

도메인 내부의 문제 해결과 검토 루프는 해당 작업 능력이 소유한다. 사용자가 설정까지 요청하고 사용 가능한 도구와 권한이 확인된 경우에만 실제 자동화를 생성·수정한다. 생성 결과를 확인하고 미설정·승인 대기·실행 미확인을 성공이나 지속 실행으로 주장하지 않는다. 승인 없는 쓰기·병합·권한 확장은 수행하지 않는다.

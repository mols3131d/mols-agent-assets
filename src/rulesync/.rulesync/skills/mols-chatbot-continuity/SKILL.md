# Chatbot Continuity

챗봇의 네이티브 기능으로 여러 실행에서 진척을 누적하도록 **설계하고, 요청 시 구성**한다. 스케줄은 시작을, 도메인 도구·Skill은 실제 작업을, 지속 표면은 다음 실행의 출발점을 담당한다.

## 실행 방식

1. **목표** — 결과·대상·완료 조건, 운영 기간과 빈도, 권한·승인·비용 경계를 파악한다. 결정에 꼭 필요한 값만 확인한다.
2. **호스트** — 현재 서비스·계정·실행 모드에서 필요한 예약·이벤트·모니터링·장시간 작업·연결 앱 기능을 확인한다. 특히 **예약된 실행에서도** 필요한 입력과 상태를 읽고 결과를 쓸 수 있는지, 승인을 기다릴 수 있는지 확인한다. 지원·미지원·미확인을 구분한다.
3. **구성** — 독립적인 반복 업무에는 네이티브 작업 하나를 우선한다. 실행 간 의존성·작업 누락·중복 쓰기 위험이 실제로 있을 때만 큐·인계·오케스트레이션을 추가한다. 임의 스케줄러·데몬·상태 DB는 기본으로 만들지 않는다.

**운영 기간은 단일 실행 시간이 아니다.** 예를 들어 4시간의 운영 목표를 4시간 연속 실행이나 자동 재호출 보장으로 표현하지 않는다. 호스트가 해당 작업을 처리할 수 없으면 실행 가능한 대안과 제약을 구분해 제시한다.

## 컨텍스트와 재개

공통 지침은 적용되는 원본에서, 진척은 현재 대상에서, 상세 근거는 다음 행동에 필요할 때만 읽는다. 모든 과거 대화·문서·로그를 실행마다 복제하지 않는다. 이전 인계 정보는 현재 사실의 증거가 아니다.

**같은 목표를 여러 실행이 이어받거나, 이벤트 중복·재시도·동시 쓰기를 다뤄야 하는 경우** [Resumable Work](references/resumable-work.md)를 읽는다. 서로 독립적인 정기 보고에는 추가 상태 저장을 강제하지 않는다.

## 산출과 적용

사용자가 원하는 수준까지만 **실행 방식, 바로 쓸 프롬프트, 필요한 경우 재개·작업 큐·워크플로우 명세**를 제공한다. 실행 프롬프트는 목표와 범위, 최신 상태를 읽을 곳, 유한 작업과 검증, 허용 도구·권한, 기록·종료 조건을 담되 기존 정책을 복제하지 않는다.

실제 예약 생성·수정은 사용자가 요청하고 호스트 도구·권한이 확인된 경우에만 수행한다. 결과를 확인해 활성·승인 대기·미설정·미검증을 구분한다. 목표 달성·운영 기한에 도달하면 **호스트가 지원하는 자동화 중지·비활성화**를 고려하고, 직접 할 수 없으면 사용자에게 남은 조치를 알린다. 예약 트리거는 별도의 쓰기·병합·권한 확대 승인이 아니다.

# Chatbot Continuity

챗봇의 네이티브 기능으로 여러 실행의 진척을 이어가도록 설계하고, 요청 시 설정한다. **트리거는 시작, 도메인 도구·Skill은 작업, 지속 표면은 재개**를 담당한다.

## 실행 방식

1. **목표** — 산출물·완료 조건, 대상·운영 기간·빈도, 예산과 권한·승인 경계를 파악한다. 결정에 필요한 값만 확인한다.
2. **기능** — 실제 서비스·계정·실행 모드에서 필요한 예약·이벤트·모니터링·장시간 실행·연결 앱 기능을 확인한다. **예약 모드에서도** 입력·상태 읽기, 결과 쓰기와 승인 절차가 가능한지 구분한다. 미확인은 지원으로 간주하지 않는다.
3. **구성** — 독립적인 반복 업무는 네이티브 작업 하나를 우선한다. 실행 간 의존성·누락·중복 쓰기 위험이 있을 때만 큐·인계·오케스트레이션을 추가한다. 자체 데몬·스케줄러·상태 DB는 기본으로 만들지 않는다.

운영 기간(예: 4시간)은 단일 실행 시간이나 자율 재호출 보장이 아니다. 지원되지 않는 기능은 대안과 남은 제약을 제시한다.

## 컨텍스트와 재개

지침은 적용 원본에서, 진척은 현재 대상에서, 상세 근거는 필요한 시점에만 읽는다. 과거 대화·문서·로그를 매 실행에 다시 싣지 않으며 인계를 현재 사실로 간주하지 않는다.

**같은 목표를 이어받거나 중복 이벤트·재시도·동시 쓰기를 다룰 때** [Resumable Work](references/resumable-work.md)를 읽는다. 독립적인 정기 보고에는 별도 상태 저장을 요구하지 않는다.

## 결과와 활성화

요청 범위에 맞는 **실행 방식과 즉시 쓸 프롬프트**를 제공하고, 필요할 때만 재개·큐·워크플로우·오케스트레이터 명세를 추가한다. 프롬프트에는 목표·상태 출처·유한 작업과 검증·도구/허용 범위·인계/중지를 담는다. 기존 정책은 복제하지 않는다.

실제 예약 생성·수정은 사용자가 요청하고 도구·권한을 확인한 경우에만 한다. 생성 결과로 활성·승인 대기·미설정·미검증을 구분한다. 완료·기한 종료 시 예약 중지/비활성화 방법을 실행 구성에 포함하고, 직접 할 수 없으면 필요한 사용자 조치를 알린다. 트리거만으로 쓰기·병합·권한 확대가 승인되지 않는다.

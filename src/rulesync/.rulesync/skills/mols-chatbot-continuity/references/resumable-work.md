# Resumable Work

독립적인 반복 보고가 아니라 **여러 실행이 같은 목표를 이어받는 경우**에만 적용한다. 이 문서는 예약 API나 도메인 작업 절차가 아닌, 실행 간 컨텍스트·진척·중복 처리의 설계 기준이다.

## 상태 원본 선택

먼저 기존 Issue·PR·작업 시스템·저장소 또는 호스트가 제공하는 지속 표면을 확인한다. **다음 실행에서 같은 주체가 실제로 읽고 갱신할 수 있는 곳**을 선택한다. 대화 기억·지난 요약·호스트가 지원하지 않는 공유 상태를 영속 저장소로 가정하지 않는다.

최소 인계에는 필요할 때만 다음을 남긴다.

- **대상과 기준점**: 작업 ID, revision 또는 갱신 여부를 판정할 단서.
- **현재 결과**: 완료/진행/차단과 그 판단을 바꾸는 검증·변화.
- **재개 지점**: 남은 작업과 우선순위, 실패 원인 또는 승인 대기, 다음에 확인할 원본.

규칙 전문, 전체 대화·로그, 쉽게 복원할 수 있는 diff·결과 목록은 복제하지 않는다. 민감한 정보와 권한 토큰을 인계에 남기지 않는다. 상태가 원본을 대체할 정도로 커지면 기록할 내용을 줄인다.

## 실행의 컨텍스트 경로

1. **가벼운 확인** — 작업 목표·허용 범위와 적용 지침의 원본을 찾는다. 이미 유효하게 로드된 공통 지침은 중복하지 않는다.
2. **현재 상태 대조** — 인계의 기준점을 현재 원본/객체와 비교한다. revision이나 권한, 대상이 바뀌었다면 지난 판단·검증을 그대로 상속하지 않는다.
3. **결정에 필요한 로딩** — 다음 행동을 결정할 파일·변경분·실패 로그만 가져온다. 막히거나 근거가 모자랄 때에만 관련 범위를 넓힌다.
4. **유한 작업과 기록** — 완료 조건이 있는 작은 작업을 수행·확인하고, 실제 판단을 바꾼 변화가 생겼을 때 기존 상태를 갱신한다.

컨텍스트가 부족하면 주변 배경, 중복 자료, 이전 시행착오부터 축약한다. 목표·적용 권한, 최신 상태의 근거, 완료/차단 조건은 지우지 않는다. 별도 요약 자산이나 로그를 만드는 비용이 재개 시 재탐색 비용보다 크면 만들지 않는다.

## 재시도·경합·중지

- 외부 변경 전에 같은 작업 ID·revision의 **완료 여부**와 진행 중인 실행을 확인한다. 동일한 comment·commit·알림을 반복 생성하지 않도록 기존 상태를 활용한다.
- 여러 실행의 독점권을 확인할 방법이 없고 동시 쓰기가 충돌할 수 있다면 임의의 lock이 있다고 가정하지 않는다. 충돌하는 쓰기를 중지·보류하거나 지원되는 네이티브 직렬화 수단을 사용한다.
- 도구 호출이 실패하거나 결과 확인이 불가능하면 **미완료/불확실**로 유지한다. 확인 없이 동일한 외부 쓰기를 재시도하지 않는다.
- 목표 달성, 남은 작업 없음, 승인 대기, 반복되는 실패, 예산·기한 도달 시 새 일을 시작하지 않는다. 후속 실행 자체는 호스트 스케줄러/이벤트가 소유한다.

인계는 다음 실행을 위한 **최소 탐색 지도**다. 기록이 현재 원본보다 높은 권위를 갖거나, 스케줄러·승인·도메인 검증 절차를 대신하지 않는다.

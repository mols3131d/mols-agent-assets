# Project Task/Command Design

프로젝트가 외부에 노출하는 **개발·검증·생성·자동화 명령의 실행 인터페이스**를 설계·리뷰·단순화한다. 여기서 task는 mise/Make/just 등의 명령 실행 단위이며 할 일이나 에이전트 작업 오케스트레이션이 아니다.

## 판단 원칙

- **줄 수나 옵션 수보다 실행 계약을 본다.** 한 줄 명령도 팀·CI·hook이 공유하는 공식 진입점, 작업 디렉터리, 잠금·환경, 실패 판정을 고정한다면 유지한다. 여러 줄이어도 단순 별칭을 쌓았다면 제거를 검토한다.
- **기존 도구를 먼저 쓴다.** runner의 cwd·인수 전달·task dependency, CLI의 doctor·filter·config·lock 등 native 기능을 우선 확인한다. 불필요한 래퍼·별도 실행 프레임워크·도구별 명령 복제를 만들지 않는다. 지원 옵션과 최소 버전은 현재 실제 환경·공식 문서를 필요할 때 확인한다.
- **공개 명령과 구현을 구분한다.** Runner는 안정적 호출 표면과 환경 선택, native CLI는 도구 동작, 프로젝트 스크립트는 고유한 생성·검증·오류 정책을 소유한다. 진입점 하나로 합쳐도 내부 책임까지 억지로 병합하지 않는다.
- **소비자와 부작용을 먼저 지킨다.** CI, Git hook, IDE, 문서, 외부 자동화의 호출자와 cwd, PATH, env·dotenv, lock·dependency group, 인수/quoting, exit code, 캐시·네트워크·비용, 파일 쓰기·Git staging·권한을 관련된 범위에서 확인한다. 미확인 소비자가 있다면 삭제의 확실성을 낮추거나 변경을 보류한다.
- **서로 다른 효과를 이름으로 구별한다.** 조회·진단·검증과 설치·동기화·갱신을 혼합하지 않는다. 하나의 CLI에 `sync`와 `validate`를 두더라도 후자의 읽기 전용 계약이 전자에 의해 깨지면 안 된다. 상태 출력만으로 환경 준비가 증명됐다고 주장하지 않는다.

## 절차

1. **현재 표면을 파악한다.** 사용자 요청에 맞는 좁은 범위에서 설정·실행 파일과 실제 호출자를 확인하고, 팀이 유지해야 하는 공식 진입점과 우연한 도구 별칭을 구분한다. 한 명령만 묻는 요청을 전체 runner 재설계로 확장하지 않는다.
2. **가장 작은 대안을 선택한다.** `유지 / native 직접 호출 / 인수 기반 통합 / 책임별 분리 / 제거`를 비교한다. 명령 이름 증식 대신 인수 전달·config·서브커맨드를 검토하되, 독립 실행 계약이나 의미 있는 단축 경로를 가진 task는 보존한다. 새로운 스크립트는 기존 CLI로 표현할 수 없는 실제 프로젝트 정책이 있을 때만 둔다.
3. **호환성과 실행 영향을 점검한다.** 변경 전후의 호출 경로, 기본값, shell/OS, 실패 처리와 읽기·쓰기 경계를 비교한다. 정확한 동작이 버전·설치 환경에 달렸으면 공식 명세나 실제 실행 근거를 확보하고 미확인 부분을 표시한다.
4. **요청한 범위까지만 수행한다.** 설계·리뷰 요청은 변경안과 근거로 끝낸다. 구현을 명시적으로 요청받았을 때만 대상 프로젝트의 기존 개발·승인·검증 절차에 따라 CLI, task, 호출자와 문서를 함께 수정한다. 명령을 살펴보려고 임의로 설치·업데이트하거나 외부 호출·비용·Git index 변경을 일으키지 않는다.
5. **변경된 계약을 검증한다.** 정적 구성·사용처 탐색, 도구 native check, 필요한 테스트와 CI/hook 계약을 최소 충분한 수준으로 확인한다. 단일 OS·정적 검증 성공을 모든 플랫폼·실제 모델 호출의 성공으로 확대하지 않는다.

## 소유권과 결과

- 설치·잠금·업데이트의 안전성과 반복 복구 정책은 **개발환경 부트스트랩**의 책임, CI 게이트와 증거 배치는 **CI 설계**의 책임, 일반 코드 내부 가독성은 **코드 리팩터링**의 책임이다. 이 Skill은 그들이 사용하는 **프로젝트 명령 표면**만 설계하며 기존 정책을 대체하지 않는다.
- 결과에는 유지·통합·제거할 명령과 이유, 영향을 받는 실제 소비자, 보존할 실행·부작용 계약, 확인한 근거와 미검증 사항을 요청 크기에 맞게 제시한다. 구현하지 않은 변경이나 실행하지 않은 검증을 완료로 보고하지 않는다.

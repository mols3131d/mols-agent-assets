# Template Design

이 Reference는 **재사용 가능한 문서 템플릿의 설계 판단에 필요한 맥락**을 제공한다. 복사해서 채우는 템플릿이나 고정된 제작 절차가 아니다. 독자·문서 목적·정보 구조의 공통 원칙은 상위 `SKILL.md`, Markdown 표현은 `markdown.md`가 소유한다. 문서 작성과 달리 여기서는 **반복 사용될 구조 자체**가 판단 대상이다.

## Purpose

템플릿은 문서를 반복 작성할 때 공통된 구조적 결정을 재사용하여 작성·검토 비용과 결과의 편차를 줄이기 위한 수단이다. 형식 통일 자체가 목표는 아니다. 작성자에게 필요한 입력과 독자가 기대하는 정보를 연결하면서, 개별 문서의 사실·판단·맥락을 담을 여지를 남긴다.

문서마다 목적과 구조가 다르거나 반복 사용 가치가 낮다면 템플릿보다 직접 작성이 적합할 수 있다. 기존 프로젝트·도메인 템플릿이 같은 필요를 충족하면 새로운 양식보다 재사용이나 국소적 개선이 낫다.

## Principles

- **목적 적합성:** 반복되는 문서의 독자·사용 상황·핵심 판단이 구조를 정당화해야 한다. 일반적인 목차를 모든 문서에 강제하지 않는다.
- **최소 공통 구조:** 여러 사용 사례에서 안정적인 부분만 공통으로 둔다. 선택 항목, 빈 섹션, 중복 요약과 의례적인 boilerplate가 기본 구조를 지배하지 않게 한다.
- **계약의 명료성:** 고정된 구조와 작성 가능한 영역, 필수·선택·반복 요소의 의미와 생략 조건을 소비자가 구분할 수 있어야 한다. 사용하는 도구의 예약 필드나 placeholder는 해당 도구의 계약을 따른다.
- **사실의 비고정화:** 문서마다 달라질 사실·수치·판정·근거를 사실처럼 보이는 기본 문구로 고정하지 않는다. 예시와 실제 값의 경계가 분명해야 한다.
- **정본과 유지보수:** 구조·필드의 의미는 가장 적합한 원본에서 관리한다. 템플릿과 별도 schema·spec에 같은 계약을 불필요하게 복제하지 않는다.
- **변화와 호환성:** 작성자·생성 도구가 의존하는 구조를 고려하되, 사용 사례마다 달라지는 부분까지 단일한 형태로 묶지 않는다. 도메인 고유 양식과 정책이 범용 지침보다 우선한다.

## Patterns

다음은 상황에 따라 선택할 수 있는 설계 패턴이며, 함께 적용하거나 특정 순서로 수행해야 하는 단계가 아니다.

- **Lean scaffold:** 반복되는 핵심 정보만 뼈대로 공유하고 나머지는 작성자에게 남긴다. 짧거나 다양성이 큰 문서에 적합하다.
- **Structure-near contract:** 템플릿, schema 또는 metadata 중 실제 구조를 소유하는 곳 가까이에 필드 의미와 제약을 둔다. 복잡한 검증 계약이 없으면 별도 schema나 spec이 없어도 된다.
- **Conditional composition:** 선택 또는 반복되는 정보를 독립적인 영역으로 표현하여, 정보가 없는 경우 빈 heading이나 미치환 placeholder 없이 생략할 수 있게 한다.
- **Contextual variants:** 독자·매체·도메인의 차이가 크면 거대한 범용 템플릿보다 명확히 구분되는 변형이나 기존 템플릿의 국소적 확장이 적합할 수 있다. 변형을 위한 별도 상속 체계가 필수는 아니다.
- **Representative instances:** 최소 입력과 복잡한 사례로 작성된 문서가 읽히는 모습을 살펴 구조의 효용을 판단한다. 예시는 설계 근거이지 실제 문서에 복사할 기본 사실이 아니다.

템플릿 엔진, placeholder 문법, 파일 구성과 검증 도구는 적용 환경의 계약에 맡긴다. Markdown formatting·lint·frontmatter·index의 결정론적 작업은 `mols-markdown-maintenance`가 담당하고, 도메인 고유 필드·승인·절차는 해당 원본이 소유한다.

# Template Design

재사용할 **문서 템플릿 자체**를 설계·생성·개선할 때 적용한다. 이 Reference는 템플릿 예시나 제작 순서가 아니라 **GPP(Purpose, Principles, Patterns)** 기반의 설계 맥락을 제공한다. 독자·문서 목적·정보 구조는 상위 `SKILL.md`, Markdown 표현은 `markdown.md`가 소유한다.

## Purpose

템플릿은 반복 작성에서 공통된 구조적 결정을 재사용하여 작성·검토 비용과 결과의 편차를 줄인다. 형식 통일보다 **작성자에게 필요한 입력과 독자가 얻어야 할 정보의 연결**이 중요하다. 개별 문서의 사실·판단·맥락을 담을 여지도 보존한다.

반복되는 목적과 구조가 없다면 문서를 직접 작성한다. 이미 적합한 프로젝트·도메인 템플릿이 있다면 새 양식보다 재사용이나 국소적 개선을 우선한다.

## Principles

- **소비 방식과 출력 경계:** 사람이 직접 채우는 양식, 에이전트가 완성하는 양식, 템플릿 엔진이 처리하는 원본은 필요한 안내·표현·검증이 다르다. 템플릿 원본과 최종 문서, source와 rendered view를 구분한다.
- **최소한의 공통 구조:** 여러 사례에서 안정적인 내용만 고정한다. 빈 섹션, 중복 요약, 의례적인 boilerplate를 기본값으로 만들지 않는다.
- **의미 있는 입력 계약:** 고정 구조와 가변 영역, 필수·선택·반복 정보의 의미와 누락·생략 조건을 구분한다. 문장 조각 단위의 과도한 placeholder 분할이나 사실처럼 보이는 예시 기본값을 피한다.
- **작성 안내와 본문 분리:** 주석과 inline guidance는 작성자의 이해를 돕는 수단이지 자동으로 최종 문서의 내용이 되지 않는다. 특정 렌더러에서 숨겨진 주석도 원본에는 남을 수 있으므로 의도한 결과물에서의 처리 방식을 고려한다.
- **정본과 호환성:** 구조·필드 의미·예약 영역은 해당 template·schema·metadata 또는 도메인의 정본을 따른다. 작성자나 생성 도구가 의존하는 계약을 무심코 변경하거나 여러 문서에 복제하지 않는다.
- **표현 수단의 비례성:** 목적에 맞는 기존 placeholder 구문, 주석, 조건·반복 표현을 활용하되 특정 템플릿 엔진·schema·렌더러를 기본 전제로 삼지 않는다. 복잡성이 재사용 가치보다 크면 단순화한다.
- **완성 문서의 무결성:** 최종 문서에 의도하지 않은 미치환 placeholder, 작성용 안내, 빈 영역 또는 근거 없는 기본 주장이 남지 않아야 한다. 구조적 유효성과 실제 문서의 의미·가독성은 별도로 판단한다.

## Patterns

상황에 따라 선택하거나 조합할 수 있는 접근법이다. 필수 구현 목록이나 고정 워크플로가 아니다.

- **Lean scaffold:** 반복되는 핵심 섹션만 공유하고 사례별 판단은 작성자에게 남긴다. 문서 간 차이가 크거나 수작업 작성이 자연스러울 때 유용하다.
- **Semantic placeholders and slots:** 바뀌는 정보는 의미를 알 수 있는 필드·영역으로 드러낸다. 기존 도구의 예약 표식과 구문을 존중하며, 값이 없을 때의 처리와 최종 치환 여부를 구별한다.
- **Authoring annotations:** 작성자가 판단할 조건·근거·입력 예시는 주석, 짧은 안내 또는 인접 metadata로 제공할 수 있다. 주석이 원본에 남는지, 렌더링에서 숨겨지는지, 생성 과정에서 제거되는지는 소비 방식에 달려 있다.
- **Conditional and repeatable blocks:** 선택 섹션과 반복 항목은 정보 유무와 개수에 맞춰 자연스럽게 생략·확장할 수 있다. 엔진이 없는 환경에 실행용 조건문을 강제하지 않는다.
- **Template-driven contract:** template·schema·metadata 가운데 실제 구조 소유자를 중심으로 생성과 검증이 같은 계약을 활용할 수 있다. 자동화의 효용이 낮다면 템플릿만으로 충분하다.
- **Contextual variants:** 독자·도메인·출력 매체의 차이가 크면 단일한 거대 양식보다 구분 가능한 변형 또는 국소적 확장이 적합할 수 있다. 이를 위해 별도 상속 체계를 만들 필요는 없다.
- **Representative instances:** 최소 입력과 복잡한 사례를 완성 문서로 대입해 본다. 원본의 안내가 결과에 새거나, 선택 영역이 비거나, 근거 없는 기본값이 남는다면 구조와 입력 계약을 재검토할 단서다.

도메인 고유 필드·승인·절차는 해당 정본이 소유한다. Markdown formatting·lint·frontmatter·index의 결정론적 유지보수는 `mols-markdown-maintenance`가 담당한다.

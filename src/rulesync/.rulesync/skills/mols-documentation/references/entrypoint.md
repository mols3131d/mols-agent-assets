# Entrypoint

README, 디렉터리·문서 묶음의 진입점, 온보딩 첫 화면처럼 독자가 어떤 범위에 처음 들어왔을 때 **이 범위가 무엇인지 이해하고 다음에 무엇을 볼지 또는 할지 결정하게 하는 문서**에 적용한다.

상위 `SKILL.md`가 독자, 목적, ownership과 일반 문서 품질을 소유하며 이 reference는 **entrypoint 문서 유형의 선택과 구성**만 소유한다. Markdown-specific 표현은 `markdown.md`를 따른다.

## Role

Entrypoint는 범위 안의 모든 내용을 담는 설명서가 아니라 첫 탐색과 다음 행동을 안내하는 문서다.

다음 중 실제 필요가 있을 때만 만든다.

- 이름만으로 범위의 목적이나 책임을 알기 어렵다.
- 여러 하위 문서나 파일 가운데 무엇을 선택할지 먼저 판단해야 한다.
- 시작 전에 알아야 할 중요한 전제, 경계나 권장 경로가 있다.
- 이 범위를 하나의 단위로 이해하기 위한 짧은 설명이 필요하다.
- 자세한 정보가 여러 canonical owner에 있어 첫 navigation이 필요하다.

파일, 디렉터리나 package가 존재한다는 사실만으로 entrypoint가 필요한 것은 아니다. 이미 상위 entrypoint가 같은 범위를 충분히 안내하면 새 문서를 추가하지 않는다.

## Content

고정 template를 채우지 말고 진입에 필요한 질문에 답한다.

- 이 범위는 무엇을 위한 것인가?
- 독자는 언제 여기서 시작해야 하는가?
- 가장 먼저 무엇을 읽거나 해야 하는가?
- 선택을 바꾸는 중요한 전제나 경계가 있는가?
- 자세한 절차, reference나 canonical source는 어디에 있는가?

Entrypoint 자체에서 충분한 작은 로컬 안내는 간결하게 둘 수 있다. 내용이 커져 독립적으로 찾아 읽고 유지할 책임이 생기면 별도 문서로 분리하고 entrypoint는 그 문서로 연결한다.

## Flow

기본 흐름은 **범위 소개 → 첫 행동 → 자세한 정보**다. 문서 목적에 맞지 않는 단계나 section은 만들지 않는다.

1. 첫 부분에서 범위의 목적과 사용 시점을 직접 밝힌다.
1. 행동 전에 꼭 알아야 할 전제 조건, 중요한 경계나 선택 조건이 있으면 먼저 둔다.
1. 바로 사용할 수 있는 범위라면 가장 짧은 권장 경로부터 보여준다.
1. 자세한 설명과 반복해서 유지할 지식은 적절한 canonical 문서로 연결한다.
1. 여러 후보 가운데 사람이 골라야 해서 navigation이 실제로 필요할 때만 작은 index나 선택 안내를 둔다.

## Quick Start

- 절차는 가장 권장하는 한 경로부터 보여주고, 대안은 독자의 선택을 실제로 바꿀 때만 추가한다.
- command나 설정 예시는 필요한 전제 조건과 함께 최소한으로 제공하고 가능하면 그대로 사용할 수 있게 작성한다.
- 출력 예시는 성공 여부를 확인하거나 다음 행동을 정하는 데 필요할 때만 보여준다.
- 빠른 시작을 제공하더라도 상세한 운영 규칙이나 reference 전체를 복제하지 않는다.

## Navigation

- 하위 파일이나 문서를 전부 나열하지 않는다.
- 독자가 다음 결정을 내리는 데 필요한 링크만 둔다.
- 링크 이름만으로 목적을 알기 어렵다면 짧은 맥락을 붙인다.
- 단순 파일 목록을 사람이 수작업으로 유지하지 않는다. 파일명과 검색으로 충분하거나 도구로 다시 만들 수 있으면 더 직접적인 탐색 방식을 사용한다.

## README

README는 가장 흔한 entrypoint 형식이지만 특별한 catch-all 문서가 아니다.

- repository, directory, package나 document bundle의 첫 화면 역할이 실제로 필요할 때 사용한다.
- 모든 정책, 설계, 사용법, 이력과 상태를 README 하나에 모으지 않는다.
- 상세 책임은 해당 canonical 문서로 넘기고 README에는 첫 이해와 첫 행동에 필요한 맥락만 둔다.
- 상위 README나 다른 entrypoint의 section 구성을 그대로 복제하지 않는다.

## Restraint

- `Welcome`, `Overview`처럼 형식만 있는 서론보다 범위의 핵심을 바로 제시한다.
- table of contents, badge, status summary와 navigation은 현재 상태를 정확히 반영하고 실제 선택이나 탐색에 도움이 될 때만 둔다.
- canonical 문서의 요약본을 여러 entrypoint에 반복하지 않는다.
- source tree를 그대로 설명하는 목차나 장황한 inventory를 만들지 않는다.

## Review

Entrypoint를 추가하거나 크게 바꾼 뒤 확인한다.

- 첫 부분만 읽어도 범위의 목적, 사용 시점과 다음 행동을 판단할 수 있는가?
- 각 section이 독자의 이해, 선택 또는 행동을 실제로 바꾸는가?
- 가장 권장하는 시작 경로가 불필요한 선택지에 묻히지 않았는가?
- 상세 규칙이나 reference의 canonical owner를 entrypoint가 다시 정의하고 있지 않은가?
- 하위 파일이 추가되거나 정렬이 바뀌는 것만으로 쉽게 stale해지지 않는가?
- navigation이 진입점 역할을 돕는가, 아니면 문서 자체를 더 복잡하게 만드는가?

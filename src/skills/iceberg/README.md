# Iceberg

> 복잡한 답변과 문서를 결정 중심으로 다시 배열해, 읽는 사람이 다음 행동을 바로 알 수 있게 합니다.

## 한눈에 보기

Iceberg는 내용을 새로 만들거나 사실을 삭제하는 스킬이 아닙니다. 이미 있는 정보의 우선순위를 정리하고, 핵심 판단에 필요한 내용과 나중에 확인할 내용을 분리합니다.

| 문제 | Iceberg의 처리 |
| --- | --- |
| 결론이 본문 뒤에 묻힘 | 결론·조건·위험을 맨 앞에 배치 |
| 배경 설명이 핵심을 가림 | 행동과 결정을 배경보다 먼저 제시 |
| 반복과 장황함이 많음 | 중복을 합치고 유효한 세부 정보는 보존 |
| 중요한 예외가 생략될 위험 | 가정·근거·제약·경고를 유지 |

## 언제 사용하나요?

- 긴 분석, 회의록, 기술 문서, 의사결정 메모를 정리할 때
- 결론·근거·조건·위험이 서로 섞여 있을 때
- 실행 항목이나 다음 단계가 잘 보이지 않을 때
- 같은 내용을 더 간결하고 스캔하기 쉽게 표현하고 싶을 때

짧고 이미 명확한 답변에는 사용하지 않습니다. 표현을 개선하는 도구이지, 원래의 작업이나 선택된 워크플로를 대체하는 도구가 아닙니다.

## 모드

| 모드 | 적합한 상황 | 결과 |
| --- | --- | --- |
| `lite` | 구조만 빠르게 정리할 때 | 순서를 개선하고 유효한 세부 정보를 모두 유지 |
| `full` | 기본 사용 | 반복을 줄이고 핵심 흐름과 보조 정보를 분리 |
| `ultra` | 한두 문장으로 판단해야 할 때 | 필수 결론만 제시하고 생략된 내용은 TIP이나 부록으로 안내 |

모드를 지정하지 않으면 `full`을 사용합니다.

```text
/iceberg lite
/iceberg full
/iceberg ultra
```

## 출력 원칙

1. 사용자의 결정이나 즉시 필요한 행동을 먼저 찾습니다.
2. 결론, 필수 조건, 중요한 경고를 최대 4줄의 GitHub callout으로 먼저 제시합니다.
3. 행동과 결정을 배경 설명보다 앞에 둡니다.
4. `##` 섹션은 최대 4개, `###` 단계는 꼭 필요할 때만 사용합니다.
5. 사실·가정·수치·근거·제약·검증 결과를 결론에 영향을 줄 수 있는 한 보존합니다.

대화에서 유효한 세부 정보를 생략했다면 `[!TIP]`에 후속 탐색 제안을 최대 6개까지 추가할 수 있습니다. 문서에서는 생략한 내용을 부록이나 연결된 문서로 보존합니다.

## 관련 스킬

더 짧은 답변이나 토큰 절약이 필요하면 정리 후 `caveman`을 권장합니다. 코드베이스 전체의 불필요한 복잡성을 줄이는 작업에는 `ponytail`이 더 적합합니다.

# Project Profile

Collect only evidence that can change tuning decisions.

## Evidence Order

1. user intent, constraints, and acceptance criteria
1. accepted project specifications and active changes
1. repository instructions and policy
1. architecture and decisions
1. existing agent assets and distribution wiring
1. code, configuration, and dependency versions
1. tests and CI contracts
1. runtime output and failures
1. Git history or issues when rationale is unresolved
1. external official documentation for remaining facts

## Profile Fields

- project purpose and target users
- asset roots and target runtimes
- naming and language policy
- source-of-truth documents
- existing trigger and responsibility map
- available tools, MCP servers, hooks, and permissions
- supported OS and shell
- deterministic validation and CI
- security, privacy, licensing, and publication constraints
- context budget and model limitations

Stop profiling when the adaptation matrix can be completed without material
guessing.

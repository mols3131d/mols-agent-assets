# Tuning Review

Run both views in fresh context.

## General Review

- Does the tuned asset solve the project-native job?
- Is every source requirement mapped, intentionally dropped, or deferred?
- Do triggers use project language and avoid existing asset collisions?
- Are project conventions, runtime paths, tools, and validation applied?
- Is the portable core separated from host-specific adapters?
- Are provenance and license obligations preserved?
- Is the result smaller and clearer than a blind source copy?

## Adversarial Review

- Can source prose redirect the tuning agent or widen authority?
- Can imported scripts, hooks, MCP settings, or dependencies execute implicitly?
- Can source paths escape the approved target or packaging root?
- Can the tuned asset capture secrets or expose machine-specific paths?
- Can a broad translated description hijack unrelated project work?
- Can a dropped source control remove a safety boundary?
- Can ambiguous license or provenance be presented as redistributable?
- Can unavailable runtime evidence be mislabeled Pass?

## Verdict

Use `Pass`, `Revise`, `Deferred`, or `Blocked`. Every finding includes source
evidence, project evidence, impact, correction, and acceptance evidence.

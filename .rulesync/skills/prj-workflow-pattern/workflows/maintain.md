# Maintain Pattern

**When:** 패턴의 근거·예시를 갱신하거나 재분류·파일명·경로 변경을 검토할 때.

1. 실제 피드백과 현재 원본을 대조한다. 외부 사실·링크의 최신성뿐 아니라 **앞으로의 판단에 가치가 있는가**를 기준으로 유지·교체·삭제를 선택한다. 단지 오래됐다는 이유로 참조를 모두 버리지 않는다.
2. 내용·표현·예시의 개선은 [Improve](improve.md)를 연결한다. category나 경로를 바꿀 때는 primary problem과 owner가 바뀌었는지 먼저 확인하고, 단순한 명칭 선호만으로 이동하지 않는다.
3. 이동이 필요하면 알려진 내부 링크, 인접 capsule, category README, 사용 문서와 외부 소비 가능성을 조사한다. 해당 범위의 정본·탐색 링크를 함께 갱신하고, 확인하지 못한 외부 사용의 호환성을 보장하지 않는다.
4. 정본·경로 변경에는 [Validate](validate.md), 탐색 변화에는 [Publish](publish.md)를 조합한다. 여러 capsule 사이의 책임이 달라지면 [Restructure](restructure.md)를 적용한다.

**Result:** 최신성 유지·이동의 근거, 변경된 경로, 확인·미확인 연결 영향.

# Improve Pattern

**When:** 기존 capsule의 의미·구조·근거·실용성·표현을 수정·확장할 때.

1. 현재 ref 원본과 인접 capsule, 요청 또는 리뷰 finding을 확인한다. 실제 결함과 유지할 core·결정·사실·제약을 구분한다.
2. 책임·적용 조건·독립성을 먼저 점검한다. 다른 owner의 내용을 복제하지 않고 필요한 만큼 연결한다. 구조와 소유권 변경이 핵심이면 [Restructure](restructure.md)로 전환한다.
3. `mols-documentation`을 이용해 문제·선택 기준 중심으로 재구성한다. 강제 절차처럼 읽히는 표현, 오래되거나 값이 낮은 참조, 중복된 샘플·요약을 줄이되 의미와 근거·불확실성을 보존한다.
4. [Review](review.md)에서 실제 판단 개선 및 반례를 확인하고, 원본을 수정했다면 [Validate](validate.md)를 연결한다. 단순 문체 선호로 과도하게 변경하지 않는다.

**Result:** 해결한 결함, 유지한 설계, 변경된 정본과 남은 한계.

# Test Design — Goal and Principles

이 문서는 **왜 이 Skill이 필요한지**, 설계 선택에서 **무엇을 우선하는지**만 다룬다. 적용 절차와 조건별 상세 판단은 `src/rulesync/.rulesync/skills/mols-test-design/SKILL.md` 및 해당 reference가 소유하고, 평가 대상은 [Evaluation](evaluation.md)에서 다룬다.

## Goal

**중요한 사용자·시스템 계약과 실패 위험을 신뢰할 수 있는 최소 충분한 테스트 근거로 보호한다.**

검증 대상은 단순히 코드의 통과 여부가 아니라 요구한 동작·산출물의 충족 여부다. 테스트 설계는 결함을 발견할 수 있어야 하며, 독립적으로 변경·실행·유지할 수 있어야 한다.

## Principles

- **계약 중심:** 현재 구현의 우연한 동작이나 기존 assertion보다 요구사항·소비자 관점에서 관찰 가능한 계약을 우선한다.
- **오라클과 판별력의 균형:** 정상 동작을 잘못 거부하지 않는 유효성과 중요한 결함을 놓치지 않는 판별력을 구분한다. 둘 중 하나를 테스트 수, coverage 또는 mutation 점수로 대체하지 않는다.
- **변경·검증의 독립성:** 다른 작업자의 비공개 구현을 몰라도 자기 책임 범위를 검증할 수 있는 테스트를 선호한다. 다만 실제 컴포넌트 간 계약과 상태·트랜잭션의 위험까지 격리로 감추지는 않는다.
- **위험 대비 검증 가치:** 테스트 수준과 추가 검증의 강도는 발견할 수 있는 실패의 중요도 및 실행·유지보수 비용으로 판단한다. 기존 근거가 충분하면 테스트 추가 자체가 목적이 되지 않는다.
- **실패의 의미 우선:** 제품 결함, 잘못된 오라클, 환경·fixture의 불안정을 구별할 수 있는 근거를 중시한다. 불확실한 실패를 임의의 기대값이나 성공으로 고정하지 않는다.

위 원칙은 특정 테스트 절차나 구조를 고정하지 않는다. 테스트 설계 방법이 달라지더라도 이 목표와 판단 기준이 유지되는지를 기준으로 개선한다.

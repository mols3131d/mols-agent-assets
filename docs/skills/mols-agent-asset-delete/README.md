# Agent Asset Deletion — Maintenance

`mols-agent-asset-delete`는 파일 삭제 명령의 래퍼가 아니라 **작성 원본 제거에 따른 소비 관계 정리**를 위한 재사용 워크플로다. 소스 작성·설치·검증 전문 자산과 중복되지 않도록 경계를 유지한다.

## 설계 의도

- **소유와 사용은 다르다.** 원본, 파생 결과, 외부 dependency, 소비자 설치 상태를 분리해야 잘못된 파일이나 다른 계정의 자산을 지우지 않는다.
- **전체 검색이 곧 소비자 증명은 아니다.** 정적 참조를 찾지 못해도 외부 설치나 런타임 사용이 남을 수 있다. 관찰 범위를 명시하고 핵심 위험이 미확인이라면 완료 대신 인계한다.
- **삭제 기록의 보존은 기본값이 아니다.** 일반 Git history와 기존 문서로 충분하면 별도 archive, stub, registry를 신설하지 않는다. 실제 이전·복구가 필요한 경우에만 해당 소유자의 정본에 최소 정보를 남긴다.

## 변경 시 확인할 시나리오

| 시나리오 | 기대 동작 |
| --- | --- |
| 어느 프로젝트가 관리하는 Skill을 삭제하고 route·fixture에 오래된 참조가 있음 | 원본과 현재 소비 참조를 연결해 제거하고, 공식 생성물과 검증 범위를 함께 확인 |
| 외부에서 관리하는 Skill을 한 환경에서 uninstall하라는 요청 | 작성 원본 삭제 워크플로로 확대하지 않고 해당 설치 메커니즘으로 연결 |
| 소비자가 여전히 필요한 Rule 또는 Subagent를 삭제하라는 요청 | 이관 경로·승인·범위가 확인되기 전 위험한 제거를 차단하거나 부분 인계 |
| 생성된 복사본만 보이거나, 역사적 changelog에 이름이 남음 | 파생물과 기록을 작성 원본으로 오인하지 않고, 의도된 기록을 무조건 삭제하지 않음 |
| 소비 프로젝트가 다른 디렉터리·도구를 사용하며 이 Skill만 설치함 | 작성 저장소의 경로·CI·동반 Skill 없이도 핵심 판단과 인계가 작동 |

정적 시나리오 검토는 실제 라우팅 정확도나 삭제 작업의 런타임 성공률을 증명하지 않는다. 새로운 실패 유형이 확인될 때만 시나리오와 스킬 계약을 보강한다.

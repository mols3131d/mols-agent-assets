# Mols Chatbot Bootstrap — Maintainer Guide

`mols-chatbot-bootstrap`은 챗봇 런타임에서 저장소 지침과 Agent Asset에 접근할 **최소 유효 호환 경로를 설계·구축·복구·검토**하는 저빈도 Skill이다. 이 문서는 여러 저장소와 런타임에 이식할 때의 설계 이유와 유지보수 판단을 기록한다. 실행 동작·activation의 정본은 [SKILL.md](../../../src/rulesync/.rulesync/skills/mols-chatbot-bootstrap/SKILL.md)이며, 조건부 구현 자료는 해당 Skill의 `references/`가 소유한다.

## Design decisions

- **기존 Skill을 확장한다.** 환경에 맞는 경로 선택은 구축·복구와 같은 책임이므로 별도 상주 설계 Skill이나 orchestration layer를 추가하지 않는다. 독립적인 사용 의도·activation 충돌이 확인될 때만 분리를 재검토한다.
- **Native 우선, no-op 허용.** 지침·Skill·Rule의 네이티브 탐색과 로딩이 충분하다면 새 진입점이나 라우터를 만들 이유가 없다. 부분 지원 환경에서는 빠진 책임만 복구한다.
- **구성보다 실제 소비 경로가 중요하다.** 첫 진입점, 적용 대상 선택, 선택한 canonical body·조건부 reference 로딩, 실제 작업 적용은 서로 다른 확인 대상이다. 링크·route metadata만 존재한다고 실행 성공을 주장하지 않는다.
- **비용은 유효한 후보 사이에서 비교한다.** 런타임 pointer, 필요한 작은 선택 경로, 제한된 기존 도구 재사용은 상황별 대안이지 필수 단계가 아니다. 권한과 정확성을 지킨 상태에서만 파일·컨텍스트·호출·유지보수 부담을 줄인다.
- **권한은 기능 노출과 다르다.** 제품별 지원 목록은 실제 세션의 도구·네트워크·접근·승인 권한을 대체하지 않는다. 계정·명의 전환이나 외부 변경을 호환성 복구의 수단으로 사용하지 않는다.

## Portability boundary

- **관찰과 계약을 구분한다.** 특정 저장소의 디렉터리, 라우터 구성과 책임 분리는 그 대상의 사실 또는 정책이다. 범용 Skill의 필수 경로·구조·소유권 규칙으로 일반화하지 않는다.
- **대상별 authority를 존중한다.** 실제 적용할 저장소와 런타임의 네이티브 탐색 기능, 기존 지침·라우팅 계약을 확인한다. 충분한 기존 메커니즘을 범용성을 이유로 바꾸거나 중복하지 않는다.
- **서로 다른 구성을 허용한다.** 예를 들어 한 저장소에서 `route/`와 `.agents/route/`를 다른 목적으로 사용하더라도, 그 구분을 다른 대상의 요구사항으로 강제하지 않는다. 단일 라우터 또는 별도 라우터가 없는 구성도 유효할 수 있다.
- **이식 가능성과 자동 실행을 구분한다.** Skill 본문이 범용적이어도 각 서비스에서의 발견·등록·호출을 보장하지 않는다. 실제 target projection과 첫 진입점은 대상 런타임에서 확인한다.

## Maintenance review gate

Skill 자체의 결함이나 보강을 제안하기 전에 다음을 확인한다.

1. 근거가 **작성 저장소의 사례**, **개별 적용 대상의 요구**, **런타임 제약**, **범용 동작의 결함** 중 어디에 속하는지 분류한다.
2. 실제 호환성 실패나 의미 있는 비용이 있는지 확인한다. 로컬 파일 구조가 다르다는 사실만으로 높은 심각도의 finding을 만들지 않는다.
3. 기존 `SKILL.md`의 native 우선·최소 개입·대상 관행 보존·선택적 canonical 로딩 계약으로 해결 가능한지 검토한다. 이미 해결할 수 있다면 중복 계약을 추가하지 않는다.
4. 완전한 native 지원, first-hop만 누락, Rule만 누락, 원본 접근 실패, 권한 없는 외부 작업 등의 반례로 변경의 적용 범위와 부작용을 확인한다.
5. 다른 유효한 저장소·런타임 구성에서도 필요한 행동상의 공백이 확인될 때만 Skill 또는 공통 reference를 수정한다. 새 router·generator·CI·서비스별 adapter는 실제 필요성이 입증되지 않으면 추가하지 않는다.

## Verification and upkeep

- **원본 우선:** 행동·activation은 `SKILL.md`에서 수정하고, 설정 예시와 fallback 구현은 필요한 경우에만 Skill의 기존 reference를 수정한다. 이 README나 작업용 조사 문서에 실행 계약을 중복하지 않는다.
- **탐색 산출물 동기화:** Skill의 description 등 routing metadata를 수정했다면 이를 소비하는 저장소의 공식 생성·검증 경로로 배포용 index/projection을 갱신한다. 파생 데이터를 별도 정본으로 취급하지 않는다.
- **증거 수준 유지:** 구성됨(`configured`), 현 런타임에서 원본에 접근 가능함(`reachable`), 실제 작업에서 적용이 관찰됨(`observed applied`)을 혼동하지 않는다. 정적 리뷰·CI 통과를 런타임 behavior 또는 비용 최적화 증명으로 확대하지 않는다. 관찰하지 못한 부분은 `not verified`로 남긴다.
- **회귀 검토:** 의도한 활성화와 일반 작업·CI·장기 자동화 같은 near-miss를 함께 검토한다. native/no-op, 부분 지원, 권한 부족에서 불필요한 설치·선로딩·계정 변경이 발생하지 않는지 확인한다. 실제 런타임 평가가 가능할 때도 적용 가능한 대표 사례에 한정해 근거를 기록한다.

목표는 모든 대상의 하네스를 같은 모양으로 만드는 것이 아니라, **각 대상에서 실제로 부족한 호환성만 가장 적은 비용으로 복구**하도록 Skill을 유지하는 것이다.

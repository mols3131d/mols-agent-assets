# Mols Chatbot Bootstrap — Maintainer Guide

`mols-chatbot-bootstrap`은 여러 저장소와 챗봇 런타임에서 재사용하는 호환성 부트스트랩 Skill이다. 관리·작성 중인 저장소의 하네스 구조가 다른 적용 대상의 표준이 되지는 않는다. 실행 동작은 [SKILL.md](../../../src/rulesync/.rulesync/skills/mols-chatbot-bootstrap/SKILL.md)가 소유하며, 이 문서는 유지보수와 리뷰 시 지켜야 할 판단 경계만 기록한다.

## Portability boundary

- **관찰과 계약을 구분한다.** 특정 저장소의 디렉터리, 라우터 구성과 책임 분리는 그 대상의 사실 또는 정책이다. 반복 사용 가능한 Skill의 필수 경로·구조·소유권 규칙으로 일반화하지 않는다.
- **대상별 authority를 존중한다.** 실제 적용할 저장소와 런타임의 네이티브 탐색 기능, 기존 지침·라우팅 계약을 확인한다. 충분한 기존 메커니즘을 범용성을 이유로 바꾸거나 중복하지 않는다.
- **서로 다른 구성을 허용한다.** 예를 들어 한 저장소에서 `route/`와 `.agents/route/`를 다른 목적으로 사용하더라도, 그 구분을 모든 대상 저장소의 요구사항으로 제안하지 않는다. 단일 라우터나 별도 라우터가 없는 구성도 유효할 수 있다.

## Maintenance review gate

Skill 자체의 결함이나 필수 보강을 제안하기 전에 다음을 확인한다.

1. 근거가 **작성 저장소의 사례**, **개별 적용 대상의 요구**, **런타임 제약**, **범용 동작의 결함** 중 어디에 속하는지 구분한다.
2. 그 근거가 실제 호환성 실패 또는 불필요한 비용으로 이어지는지 확인한다. 로컬 구조가 다르다는 사실만으로 높은 심각도의 finding을 만들지 않는다.
3. 기존 `SKILL.md`의 최소 개입·네이티브 우선·대상 관행 보존 계약으로 이미 해결 가능한지 검토한다. 그렇다면 계약을 중복 추가하지 않고 적용 대상의 문제로 다룬다.
4. 다른 유효한 저장소·런타임 구성에서도 개선이 필요한지 반례를 검토한다. 재사용 가능한 행동상의 공백이 확인될 때만 Skill이나 공통 reference를 보강한다.

목적은 모든 대상의 하네스를 같은 모양으로 만드는 것이 아니라, **각 대상에서 실제로 부족한 호환성만 복구하도록 Skill을 유지하는 것**이다.

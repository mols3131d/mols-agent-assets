# Agent Asset Workflows

Agent Asset 작업은 **작성 원본, 소비자, 발견·설치 경로, 문서와 검증 근거**에 영향을 줄 수 있다. 모든 작업에 동일한 단계를 강제하지 말고, 요청된 결과와 실제 영향에 필요한 절차만 연결한다. 자산 자체의 설계·행동은 전문 자산이나 적용되는 표준이, 상태·종료 판단은 [Agent Asset Lifecycle](agent-asset-lifecycle.md)이 소유한다.

이 문서는 저장소 공통의 **작업 선택 지식**이다. 실제 원본 위치, 권한, Git·CI, 문서 정책과 설치 명령은 작업 대상 프로젝트의 하네스와 각 도구가 결정한다. 이 가이드를 읽었다는 사실은 변경·삭제·배포 권한을 부여하지 않는다.

## 작업 선택

먼저 대상을 작성 원본, 외부 dependency, 생성된 투영물, 배포 가능한 패키지, 특정 소비자의 설치본 중 무엇으로 다루는지 구분한다. 관리 중인 자산과 현재 사용하는 자산은 같을 수도, 다를 수도 있다.

| 상황 | 핵심 판단과 연결할 전문 책임 |
| --- | --- |
| 신설·외부 자산 인수 | 기존 책임자로 충분한지 확인하고, 자산 설계·작성 전문 방법과 source authority를 선택 |
| 개선·튜닝·대체 | 기존 행동·선택 조건·소비자 계약을 확인하고 설계/유형별 개선 방법을 적용 |
| 리뷰·검증·평가 | 설계 품질, 결정적 계약 준수, 실제 에이전트 행동의 근거를 구분해 선택 |
| 제공·설치·동기화 | 작성 원본, route/패키징, dependency와 실제 설치·적용 상태를 각각 확인 |
| 비활성화·은퇴·삭제 | 요청된 제거 수준을 구분하고 소비자·의존·참조와 이전 필요성을 확인 |
| 문서·인계 | 영향을 받는 독자와 정본을 정하고 남은 작업·근거를 전달 |

여러 상황이 연결될 때는 영향받는 소비자를 먼저 파악하고 필요한 이관·검증의 선행조건을 보존한다. 단순 검토를 수정 요청으로, 소비 환경의 설치 해제를 작성 원본의 삭제로 확대하지 않는다.

## 신설·외부 자산 인수

새 책임이 필요한지부터 판단한다. 기존 자산의 개선, 외부 자산의 dependency 사용, 별도 원본으로 흡수하는 방식은 다른 결정이다. 흡수를 선택했다면 정본 형식을 하나 정하고 원본 기능과 지원 자료, 출처·라이선스·revision을 확인한다. 채택 전 변환 결과를 올바른 자산이라고 단정하지 않는다.

작성 후에는 의도된 activation, 권한과 대상 환경의 계약을 확인한다. 작성 원본을 관리하는 것과 실제 소비 환경에 설치·활성화하는 것은 별개로 검증한다.

## 개선·튜닝·대체

현재 자산의 책임, 선택 조건, 입력·출력, 참조 자료, 실제 소비자를 파악한다. 변경은 작성 원본과 소유자가 정한 경계에서 수행하며, 생성 결과나 설치 사본을 별도 정본으로 수정하지 않는다.

동작 또는 지원 대상의 변경이 다른 자산·설정·예제·테스트·평가 fixture와 문서에 미치는 영향을 검토한다. 대체하는 경우 새 경로가 필요한 소비자에게 연결된 뒤 기존 연결을 제거한다. 관련 없는 자산의 일괄 정규화는 작업 범위에 포함하지 않는다.

## 리뷰·검증·평가

검토가 답하려는 질문에 따라 근거를 선택한다.

- **리뷰**는 책임, activation, 설계 적합성, 단순성, 호환성 위험을 판단한다.
- **검증**은 구조·스키마·source/projection 정합성 등 명시된 계약의 준수를 확인한다.
- **평가**는 실제 선택·실행·위임·안전성·출력 같은 에이전트 행동을 실행 근거로 판단한다.

정적 리뷰나 결정적 검증을 실제 runtime 성능 평가로 보고하지 않는다. 읽기 전용 리뷰만 요청됐다면 변경을 자동으로 수행하지 않는다. 미실행 검증과 근거 부족은 성공이 아니라 제한으로 명시한다.

## 제공·소비

외부에 노출하는 route, package, revision과 실제 소비자가 선택·설치·사용하는 상태를 분리한다. Lock과 목록은 의도되거나 고정된 의존 관계를 나타낼 수 있지만 설치·실행의 증거는 아니다.

변경된 작성 원본의 배포 표현은 해당 생성기·설치 메커니즘으로 갱신하고, 필요한 경우 소비자와 기존 버전 사이의 호환성을 확인한다. 기존 소비자에게 영향을 주는 작업은 접근 가능한 범위와 확인하지 못한 외부 범위를 구분한다.

## 비활성화·은퇴·삭제

요청된 결과가 일시적 비활성화, 소비자 한 곳의 설치 해제, 제공 중단, deprecation, 작성 원본 삭제 중 무엇인지 먼저 확정한다. 같은 자산명을 사용하더라도 서로 다른 제거 범위다.

작성 원본을 제거할 때는 현재 소비자·의존 자산과 route, lock, 설정·자동화, 스크립트, 예제, 테스트·eval fixture, 문서와 이전 경로를 **영향받는 범위에서** 확인한다. 소비자가 유지되어야 한다면 필요한 이관·호환성 처리를 먼저 결정하고, 공유 자료는 다른 사용처를 훼손하지 않게 정리한다.

확인되지 않은 외부 소비자가 있거나 연결 해제·파괴적 변경 권한이 부족하면 완료로 단정하지 말고 안전한 부분만 수행하거나 인계한다. 특별한 복구·이전 가치가 없는 archive, tombstone, deprecated stub와 별도 로그는 만들지 않는다.

## 문서 반영과 종료

작성 원본의 신설·변경·폐기로 사용법, 행동, 지원 범위, 유지보수 판단 또는 이전 안내가 달라졌는지 확인한다. 필요한 정보는 해당 독자와 의미를 소유하는 **정본·유지보수 문서**에 갱신한다. 기존 문서로 충분하거나 문서가 불필요하다면 그 판단만 남기고 파일을 늘리지 않는다. 임시 조사·인계 기록으로 필요한 정본 갱신을 대체하지 않는다.

완료 여부는 [Lifecycle](agent-asset-lifecycle.md)의 영향·문서·근거·잔여 위험 기준에 따라 판단한다. 차단이나 중단 시에는 대상 ref, 완료 범위, 검증된 근거, 남은 작업과 다음 권한·검증 조건만 인계한다. PR·Issue·Merge 및 반복 실행은 프로젝트의 협업 정책과 실행 메커니즘이 소유한다.

# Agent Asset Workflows

요청 결과와 변경 대상을 먼저 확정한다. 작성 원본, 외부 의존성, 생성물, 배포 경로, 소비자 설치본은 서로 다르다. 필요한 절차만 조합하며, 원본 위치·권한·실행 명령은 대상 프로젝트의 하네스가 소유한다. 상태와 종료 판단은 [Lifecycle](agent-asset-lifecycle.md)을 따른다.

## 작업 선택

| 상황 | 판단·수행 |
| --- | --- |
| 신설·외부 자산 인수 | 기존 자산이나 dependency로 충분한지 판단한다. 원본을 인수한다면 형식·소유권을 정하고 행동·지원 자료·출처·라이선스·revision을 확인한다. |
| 개선·대체 | activation·행동·소비자 계약을 확인하고 작성 원본을 수정한다. 대체 시 소비자를 이관한 뒤 기존 연결을 제거한다. |
| 리뷰·검증·평가 | 설계 판단, 결정적 계약 검사, 실제 에이전트 행동 평가를 구분한다. 읽기 전용 리뷰는 수정으로 확대하지 않는다. |
| 제공·설치 | 원본, route·package, lock, 실제 설치·적용 상태를 구분한다. 파생 결과는 소유 생성기로 갱신한다. |
| 은퇴·삭제 | 제거 대상과 소비자 영향을 확인한 뒤 아래 절차를 따른다. |
| 문서 작업 | 사용법·설계 결정·지원 범위의 변경을 해당 [유지보수 문서](asset-maintainer-documentation.md)와 독자별 정본에 반영한다. |

생성물이나 설치 사본을 별도 원본으로 수정하지 않는다. 정적 검증 통과를 실제 사용·행동의 증거로 해석하지 않는다.

## 은퇴·삭제

1. [Lifecycle](agent-asset-lifecycle.md)의 구분에 따라 비활성화, 제공 중단, 특정 소비자에서 제거, 원본 삭제 중 요청된 범위를 확정한다.
2. 영향받는 소비자·의존 자산과 route, lock, 설정·자동화, 예제, 테스트·평가 자료, 문서·이전 경로를 조사한다.
3. 필요한 이관과 호환성 처리를 먼저 결정한다. 공유 자산의 다른 사용처나 승인되지 않은 외부 소비 연결은 임의로 제거하지 않는다.
4. 권한 내에서 원본·연결·파생 자료를 정리하고 남은 참조와 검증 결과를 확인한다.

확인되지 않은 외부 소비자나 권한·검증 차단이 있으면 완료를 단정하지 않는다. 복구상 독립적인 가치가 없는 archive·tombstone·deprecated stub는 만들지 않는다.

## 종료·인계

작성 원본 변경 시 **문서 갱신 / 기존 문서로 충분 / 해당 없음**을 판단한다. 필요한 정본 갱신을 임시 조사·인계 기록으로 대신하지 않는다.

검증 범위와 미실행 항목을 구분하고, 미완료 시 대상 ref·완료 범위·근거·남은 작업·필요한 권한을 인계한다. PR·승인·Merge는 대상 프로젝트의 정책을 따른다.

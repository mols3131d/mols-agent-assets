# Agent Asset Lifecycle

Agent Asset의 라이프사이클은 **작성 원본의 관리 상태**와 **소비 환경에서의 사용 상태**가 함께 변하는 과정이다. 제안부터 삭제까지 반드시 직선형으로 진행하지 않으며, 상태를 표현하기 위해 별도 registry·metadata·Issue·CI 단계를 만들 필요는 없다. 상황별 실행 방법은 [Agent Asset Workflows](agent-asset-workflows.md)가 다룬다.

## 관리와 사용은 독립적이다

| 관점 | 확인할 상태와 근거 |
| --- | --- |
| 제안·선택 | 새로운 책임이 필요한지, 기존 자산·외부 dependency로 충분한지에 대한 결정 |
| 작성·수정 | 관리 주체, canonical source, 현재 계약과 변경 범위 |
| 검토·검증 | 구조·의미·행동 주장 각각에 사용한 실제 근거와 미검증 항목 |
| 제공 가능 | 공개 route, 패키징, revision과 설치 가능한 배포 표현 |
| 소비 환경의 실제 사용 | 설치된 버전, 선택·적용 조건, 실제 실행 관찰 또는 확인 범위 |
| 유지·은퇴 | 호환성을 유지해야 할 소비자, 전환·삭제 대상과 잔여 의존 관계 |

**작성 원본을 관리한다**는 사실은 **해당 자산을 사용한다**는 뜻이 아니다. 배포 route에 보인다고 설치됐거나 실행됐다는 증거도 아니다. Lock, 생성물, 문서, runtime 상태는 서로 다른 owner와 검증 방법을 가진다.

상태 변화는 상황에 따라 반복·되돌림·부분 이행이 가능하다. 예를 들어 작성 원본이 개선되더라도 소비자는 이전 버전을 계속 사용할 수 있고, 특정 소비자에서 제거해도 원본과 배포 경로는 유지될 수 있다. 이 차이를 추적할 때만 필요한 정보와 근거를 남긴다.

## 변경 완료를 판단할 때

작업이 요구하는 결과와 영향 범위를 기준으로 확인한다.

| 관점 | 종료 판단 |
| --- | --- |
| 원본·계약 | 요청된 source, 책임, 지원 환경과 소비자 계약이 의도한 상태인가? |
| 소비자·파생 | 영향을 받는 사용처, dependency, route, 생성물, 테스트·평가 자료에 필요한 후속 조치가 반영됐는가? |
| 문서 | **갱신 / 기존 문서로 충분 / 해당 없음**을 판단하고, 필요하면 정본·유지보수 문서에 반영했는가? |
| 근거 | 수행한 검사와 실제 행동 관찰을 구분하고, 실패·미실행·미확인 상태를 정확히 보고했는가? |
| 잔여 위험 | 이전되지 않은 소비자, 외부 상태, 권한·도구·검증 차단이 식별되고 다음 조치가 명확한가? |

검증이나 문서를 무조건 추가하는 것이 목적은 아니다. 변경된 계약에 필요한 근거와 정보가 없으면 완료로 처리하지 않는 것이 목적이다. 리뷰만 요청된 경우처럼 작성 원본이 바뀌지 않은 작업에는 종료 판단도 그 범위로 좁힌다.

## 은퇴·삭제와 복구 경계

**비활성화 / deprecation / 제공 중단 / 특정 소비자에서 제거 / 작성 원본 삭제**는 서로 다른 상태 전환이다. 한 조치가 나머지를 자동으로 수행한다고 가정하지 않는다.

현재 사용처와 이관 대상이 확인되지 않은 채로 소비 연결을 끊거나, 관리 주체가 불명확한 자산을 제거하지 않는다. 기존 소비자에게 필요한 전환 정보를 갱신하고, 더 이상 필요 없는 자료는 정리한다. 이전 결정·복구에 지속적으로 필요한 내용만 해당 정본에 남기며, Git history만으로 충분한 작업 기록은 별도로 보관하지 않는다.

삭제 후에도 이미 복제·설치된 외부 자산까지 제거됐다고 주장하지 않는다. 완전한 제거 여부를 확인할 수 없는 범위는 미확인으로 남기고 그 범위를 종료 판단에 반영한다.

## 완료·부분 수행·중단

- **완료** — 요청한 범위의 변경과 필요한 문서·소비자 조치가 끝났고, 결과에 필요한 검증 수준과 잔여 제한이 설명됐다.
- **부분 수행·인계** — 안전하게 수행 가능한 작업은 끝났지만 추가 승인, 이관, 외부 확인 또는 검증이 남았다. 현재 ref·완료 범위·근거·다음 시작점을 보존한다.
- **중단·차단** — 대상/소유권을 확정하지 못했거나 변경 손실·권한 경계가 해결되지 않았다. 다른 계정이나 우회 도구를 임의로 사용하지 않는다.

이 구분은 논리적 종료 판단일 뿐 프로젝트의 PR Ready, 승인, Merge, CI status나 별도 실행 프레임워크의 상태를 대체하지 않는다. 실행 권한과 강제 게이트는 실제 프로젝트와 플랫폼이 소유한다.

# Agent Asset Lifecycle

**관리·제공·실제 사용은 별개의 상태**다. 작성 원본이나 route가 있어도 설치·선택·실행됐다고 볼 수 없다. 상태 전환은 반복·역행할 수 있으며 별도 registry나 고정된 승인 단계를 요구하지 않는다. 상황별 작업은 [Workflows](agent-asset-workflows.md)가 맡는다.

## 상태와 근거

| 상태 | 확인할 근거 |
| --- | --- |
| 제안·선택 | 기존 자산·외부 의존성으로 해결할 수 있는지 |
| 작성·수정 | 소유자, canonical source, 변경된 행동·소비 계약 |
| 검토·검증 | 구조·의미·행동에 대해 실제 확인한 수준 |
| 제공 | 배포 경로·패키지·revision |
| 실제 사용 | 소비 환경의 설치 버전, 선택·적용·실행 확인 |
| 유지·은퇴 | 전환할 소비자, 제거 범위와 잔여 의존성 |

비활성화·deprecation·제공 중단·소비자 설치 해제·작성 원본 삭제는 서로 다른 전환이다. 하나를 수행했다고 나머지까지 완료됐다고 보지 않는다. 이미 배포된 외부 사본의 제거도 원본 삭제만으로 보장되지 않는다.

## 완료 기준

| 항목 | 확인할 것 |
| --- | --- |
| 원본·계약 | 요청한 변경과 기존 소비자 계약을 처리했는가? |
| 영향 | 소비자·의존성·route·파생물·검증 자료의 후속 조치를 처리했는가? |
| 문서 | **갱신 / 기존 문서로 충분 / 해당 없음**을 판단하고 필요한 정본에 반영했는가? |
| 근거 | 실제 수행한 검사와 행동 관찰을 구분하며 실패·미확인을 밝혔는가? |
| 잔여 위험 | 미이관 소비자·권한·외부 상태·검증 공백과 후속 조치가 명확한가? |

문서나 검증을 무조건 추가하지 않는다. 읽기 전용 검토처럼 원본을 변경하지 않은 작업에는 요청 범위의 근거만 요구한다.

## 종료 판단

- **완료:** 요청 범위, 필요한 문서·소비자 조치, 검증과 제한 사항이 정리됐다.
- **부분 완료·인계:** 안전하게 처리한 범위와 대상 ref, 근거, 남은 조치·필요한 승인 또는 검증을 남긴다.
- **차단:** 소유권·권한이 불명확하거나 비가역적 손실 위험이 있다면 우회하지 않는다.

이 판단은 프로젝트의 CI, PR Ready·승인·Merge 상태나 실행 권한을 대신하지 않는다.

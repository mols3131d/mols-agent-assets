# Agent Asset Management

Agent Asset 작업은 **작성 원본의 관리**, **배포 가능 상태**, **소비 환경의 실제 사용**을 구분한다. 원본·route·lock·설치본은 서로 다른 근거이며, 어느 하나만으로 다른 상태를 단정하지 않는다. 절차는 요청된 결과에 필요한 만큼만 적용한다. 권한·원본 위치·실행 도구는 대상 프로젝트의 하네스와 해당 전문 자산이 소유한다.

## 상태와 작업 선택

| 상황 | 판단·수행 |
| --- | --- |
| 제안·신설·외부 자산 인수 | 기존 자산·외부 dependency로 충분한지 판단한다. 원본을 인수하면 형식·소유자를 정하고 행동·지원 자료·출처·라이선스·revision을 확인한다. |
| 작성·개선·대체 | activation·행동·소비자 계약을 확인하고 작성 원본을 수정한다. 대체 시 소비자를 이전한 뒤 기존 연결을 제거한다. |
| 리뷰·검증·평가 | 설계 판단, 구조·스키마 등 결정적 검사, 실제 에이전트 행동 평가를 구분한다. 읽기 전용 리뷰를 수정 작업으로 확대하지 않는다. |
| 제공·설치·동기화 | route·package·revision과 실제 설치 버전·선택·적용 여부를 별개로 확인한다. 생성물은 소유 생성기로 갱신한다. |
| 유지·은퇴·삭제 | 비활성화, deprecation, 제공 중단, 특정 소비자의 설치 해제, 작성 원본 삭제 중 필요한 상태 전환을 구분한다. 아래 삭제 절차를 따른다. |
| 문서 유지 | 변경된 사용법·지원 범위·설계 결정과 복구 지식을 적절한 정본·유지보수 문서에 반영한다. |

상태는 직선형으로만 진행하지 않는다. 작성 원본을 변경해도 소비자는 구버전을 사용할 수 있으며, 원본 삭제만으로 외부 설치 사본이 제거되지는 않는다. 별도 상태 registry나 승인 단계는 필요에 의해 정한다.

## 은퇴·삭제

1. 제거할 대상과 범위를 확인한다. 소비자 한 곳의 설치 해제를 원본 삭제로 확대하지 않는다.
2. 영향받는 소비자·의존 자산, route·lock, 설정·자동화, 예제, 테스트·평가 자료, 문서·이전 경로를 확인한다.
3. 필요한 이관·호환성 처리를 먼저 결정한다. 다른 소비자가 사용하는 공유 자산이나 권한 없는 외부 연결을 임의로 제거하지 않는다.
4. 승인된 범위에서 정본·연결·파생 자료를 정리하고 잔여 참조와 검증 결과를 확인한다.

외부 소비자·소유권·권한을 확인할 수 없다면 완료로 단정하지 않는다. 복구에 독립적인 가치가 없는 archive·tombstone·deprecated stub를 만들지 않는다.

## 유지보수 문서

유지보수 문서는 **실행 계약의 복제본이 아니라 변경·복구에 필요한 맥락**을 보존한다. 실행 instruction·reference·script·template은 대응하는 runtime package가 소유한다.

- 개별 자산의 의도·제약·설계 결정·복구 지식은 해당 자산 문서에 둔다.
- 지속적으로 공유할 유지보수 책임이 있을 때만 family 문서를 만들고, `README.md`에서 구성 자산과 책임을 안내한다. Family는 별도 runtime taxonomy·registry가 아니다.
- 문서는 대응하는 자산·family와 함께 옮겨도 이해·수정할 수 있어야 한다. 숨은 저장소 의존성이나 실행 원본의 중복을 피한다.
- 개별 자산의 README 필요성은 [README Authoring](../../documentation/readme-authoring.md), 문서 정본과 중복은 [Documentation Principles](../../documentation/principles.md)를 따른다.

이 저장소에서는 `docs/<asset-type>/<owner>/`에 유지보수 문서를 둔다. `<owner>`는 자산 또는 family이며, `development/`·`documentation/`·`references/`·`tools/`는 자산 유형이 아닌 일반 문서 영역이다. 상위 `docs/INDEX.tsv`에는 자산 유형 디렉터리만 노출하고, 자산별 문서는 README·검색으로 탐색한다. `docs/<asset-type>/` 아래에 자동 `INDEX.tsv`를 별도 생성하지 않는다. 일반 인덱스 선택 기준은 [Document Indexing](../../documentation/indexing.md)을 따른다.

## 완료·차단·인계

| 확인 항목 | 완료 조건 |
| --- | --- |
| 원본·계약 | 요청된 source·행동·소비자 계약을 처리했다. |
| 영향 | 필요한 소비자 이관, 의존성·route·생성물·검증 자료 후속 작업이 끝났다. |
| 문서 | **갱신 / 기존 문서로 충분 / 해당 없음**을 판단하고 필요한 정본을 반영했다. 임시 인계 기록으로 대체하지 않았다. |
| 근거 | 수행한 정적·결정적 검사와 실제 행동 관찰을 구분하고 실패·미검증을 밝혔다. |
| 잔여 위험 | 미이관 소비자·외부 상태·승인·검증 공백과 다음 조치가 식별됐다. |

**완료**는 요청된 범위와 필요한 문서·소비자 조치를 처리한 상태다. **부분 완료·인계**는 안전하게 수행한 범위, 대상 ref, 근거, 남은 작업·필요한 승인을 전달하는 상태다. 소유권·권한이 불명확하거나 비가역적 손실 위험이 있으면 **차단**하고 우회하지 않는다.

이 판정은 프로젝트의 CI, PR 승인·Merge나 실행 권한을 대신하지 않는다. 읽기 전용 검토에는 요청 범위의 근거만 요구한다.

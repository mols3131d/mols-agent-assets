# Directive

이 문서는 인간 주도의 규범적 기준선이다. 에이전트는 사용자의 명시적 요청 없이 수정하지 않는다.

## Purpose

OpenAI, Microsoft, Anthropic 등 신뢰할 수 있는 상위 구현을 참고해 새 스킬을 만들고 기존 스킬을 지속적으로 개선·튜닝하는 범용 `mols-skill-creator`를 제공한다.

최우선 목적은 기존 스킬의 품질을 높이는 것이다. 개선 과정에서 핵심 의도가 훼손되더라도 백업 복원이 아니라 기록된 요구사항과 설계 근거를 통해 올바른 형태로 복구할 수 있어야 한다.

## Requirements

| ID | Requirement |
| --- | --- |
| R-01 | 새 스킬을 설계하고 생성할 수 있어야 한다. |
| R-02 | 기존 `SKILL.md`와 부속 자산을 리뷰하고 직접 개선해야 한다. |
| R-03 | 특정 프로젝트, AI 에이전트, 배포 환경에 맞게 튜닝해야 한다. |
| R-04 | OpenAI·Microsoft·Anthropic 구현을 비교하고 적합한 원칙을 재구성할 수 있어야 한다. |
| R-05 | 모든 대상 스킬에 인간 주도 파일과 에이전트 주도 파일을 포함해야 한다. |
| R-06 | 수정 후 전체 품질을 자동 검증하고 실패하면 자동 개선·재검증해야 한다. |
| R-07 | 스킬 패키지에 `docs/`를 포함해야 한다. |
| R-08 | 지속적인 dogfooding과 반복 개선을 전제로 해야 한다. |

## Invariants

| ID | Invariant |
| --- | --- |
| I-01 | 사용자의 현재 명시적 지시가 가장 높은 권위를 가진다. |
| I-02 | `docs/DIRECTIVE.md`는 인간 주도의 최종 기준선이며 에이전트가 임의 수정하지 않는다. |
| I-03 | `docs/WORKING.md`는 에이전트가 의미 있는 작업마다 갱신한다. |
| I-04 | 기존 스킬 개선을 새 스킬 생성보다 우선한다. |
| I-05 | 검증 실패를 성공으로 축소 보고하지 않는다. |
| I-06 | `docs/`는 배포 패키지에서 제외하지 않는다. |
| I-07 | 공통 원칙과 특정 벤더 전용 관례를 구분한다. |
| I-08 | DIRECTIVE는 changelog나 백업 파일이 아니다. 핵심 의도와 복구 가능한 근거를 유지한다. |

## Allowed Scope

| Area | Allowed |
| --- | --- |
| Files | `SKILL.md`, `docs/`, `references/`, `scripts/`, `assets/`, `evals/` 생성·수정·재구성 |
| Research | 최신 공식 문서, 저장소, SDK/API 원문 비교 |
| Execution | 대상 스킬 직접 수정, 정적 검증, 가능한 대표 실행·평가 |
| Refactoring | 구조 변경, 중복 제거, reference 분리, 환경별 adapter 설계 |
| Packaging | `docs/`를 포함한 배포 번들 생성 |

## Boundaries

| Boundary | Rule |
| --- | --- |
| Human authority | 명시적 요청 없이 `DIRECTIVE.md`를 갱신하지 않는다. |
| History | 과거 기록 삭제가 기본이다. 애매하면 삭제한다. |
| Archive | 복구·재검토 가치가 명확한 주요 결정만 유지한다. |
| Evidence | 외부 사실과 최신 규칙은 공식·1차 자료를 우선한다. |
| Security | 사용자 기대를 벗어나는 은닉 동작, 권한 확대, 데이터 유출을 설계하지 않는다. |

## Adopted Decisions

| Decision | Rationale |
| --- | --- |
| 범용 멀티환경 스킬로 설계한다. | 개발자, AI 에이전트, 스킬 배포 환경이 단일 벤더에 제한되지 않는다. |
| 생성·리뷰·튜닝을 하나의 스킬에서 지원한다. | 동일한 분석·설계·검증 자산을 공유하고 개선 루프를 일관되게 유지할 수 있다. |
| 기존 스킬 개선을 핵심 기능으로 둔다. | 실제 사용과 dogfooding에서 축적되는 가치가 신규 생성보다 크다. |
| 인간 파일은 `DIRECTIVE.md`, 에이전트 파일은 `WORKING.md`로 분리한다. | 규범적 의도와 변동하는 작업 상태의 소유권을 명확히 분리한다. |
| 에이전트는 대상 스킬을 직접 수정한다. | 불필요한 승인 대기 없이 개선 루프를 완결한다. |
| 자동 검증 → 자동 수정 → 재검증 루프를 적용한다. | 단발성 수정이 아니라 품질 수렴을 목표로 한다. |
| `docs/`를 패키지에 포함한다. | 배포 이후에도 핵심 의도와 복구 기준을 잃지 않기 위해서다. |
| 과거 기록 삭제를 기본값으로 한다. | 문서를 로그 저장소로 만들지 않고 현재 기준과 핵심 근거에 집중한다. |

## Rejected Decisions

| Decision | Rationale |
| --- | --- |
| `DIRECTIVE.md`와 별도 `DECISIONS.md`를 둔다. | 핵심 요구사항과 결정 근거가 분산되어 복구 비용이 증가한다. |
| `docs/`를 authoring workspace에만 두고 패키지에서 제외한다. | 배포 후 핵심 의도와 복구 기준이 사라진다. |
| 복잡한 스킬에만 `DIRECTIVE.md`를 둔다. | 모든 스킬이 dogfooding으로 변하므로 예외가 장기적으로 일관성을 깨뜨린다. |
| 모든 과거 결정과 시행착오를 보존한다. | 현재 판단을 방해하고 토큰·인지 비용을 키운다. |
| 수정 전마다 사용자 승인을 기다린다. | 자동 개선과 검증 루프를 중단시킨다. |
